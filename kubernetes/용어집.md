# 용어집 — Kubernetes

자주 쓰는 용어를 "X는 Y다" 한 줄 정의 + 실무에서 만나는 지점으로 정리. 관련 노트: [[구성도]], [[클러스터]], [[설치(k3d)]], [[목차]].

## 클러스터 구조

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **클러스터(Cluster)** | 노드 여러 대를 하나의 컴퓨팅 자원처럼 묶은 단위. 컨트롤 플레인 + 워커 노드 | `k3d cluster create`, kubeconfig 의 context 하나 = 클러스터 하나 |
| **노드(Node)** | Pod 를 실행하는 머신(물리·VM·컨테이너). kubelet 이 등록 | `kubectl get nodes`. k3d 는 컨테이너 1개 = 노드 1개 |
| **컨트롤 플레인(Control Plane)** | 클러스터를 제어하는 컴포넌트 묶음. API 서버·스케줄러·컨트롤러 매니저·etcd | k3s/RKE2 의 `server` 역할. 죽으면 배포·복구·kubectl 정지 |
| **워커 노드(Worker)** | 워크로드(Pod)만 실행하는 노드 | k3s/RKE2 의 `agent` 역할 |
| **server / agent** | k3s·RKE2 용어. server = 컨트롤 플레인 + agent, agent = 워커 | 표준 용어로는 control-plane / worker. [[구성도]] |
| **API 서버(kube-apiserver)** | 모든 요청의 창구. kubectl·컨트롤러·kubelet 전부 여기로 통신 | 6443 포트. kubeconfig 의 `server:` 주소 |
| **etcd** | 클러스터의 모든 상태를 저장하는 키-값 저장소. 과반(쿼럼) 합의로 일관성 유지 | server 가 3대인 이유. 2379-2380 포트. 백업 = etcd 스냅샷 |
| **쿼럼(Quorum)** | etcd 멤버의 과반. 3개면 2, 5개면 3. 과반이 살아 있어야 쓰기 가능 | 2대 동시 장애 시 API 정지의 원인 |
| **스케줄러(kube-scheduler)** | 새 Pod 를 어느 노드에 둘지 결정 | `resources.requests`, taint/toleration, nodeSelector 가 판단 근거 |
| **컨트롤러 매니저(kube-controller-manager)** | "원하는 상태"와 "현재 상태"를 계속 비교해 맞추는 루프들 | Deployment 의 replica 수 유지, 노드 장애 시 Pod 재생성 |
| **kubelet** | 각 노드에서 Pod 를 실제로 띄우고 감시하는 에이전트. 노드를 API 서버에 등록 | 10250 포트. 이게 없으면 노드가 `kubectl get nodes` 에 안 나옴 |
| **kube-proxy** | Service 의 가상 IP 를 실제 Pod 로 전달하는 네트워크 규칙 관리 | iptables/ipvs 규칙. Service 가 동작하는 원리 |
| **컨테이너 런타임** | 컨테이너를 실제로 실행하는 소프트웨어 | containerd (k3s·RKE2 기본). Docker 는 이미지 빌드용이고 노드 런타임이 아님 |
| **CNI(Container Network Interface)** | Pod 네트워크를 만드는 플러그인 규격. Pod 에 IP 를 주고 노드 간 통신 연결 | Flannel(k3s), Canal(RKE2), Calico, Cilium. 생성 후 변경 불가 |
| **kubeconfig** | kubectl 이 접속할 클러스터 주소·인증서·context 를 담은 파일 | `~/.kube/config`. `kubectl config get-contexts` |
| **context** | kubeconfig 안의 "클러스터 + 사용자 + 네임스페이스" 조합 이름 | `kubectl config use-context k3d-lab` |
| **배포판(Distribution)** | Kubernetes 를 설치·운영 가능한 형태로 묶은 제품 | k3s, RKE2, kubeadm, EKS. API 와 YAML 은 전부 같음 |

## 워크로드

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **Pod** | Kubernetes 가 실행하는 최소 단위. 컨테이너 1개 이상이 네트워크·스토리지를 공유 | 직접 만들지 않고 Deployment 등이 만듦. `kubectl get pods` |
| **컨테이너(Container)** | 이미지에서 실행된 프로세스. Pod 안에 들어감 | `kubectl logs <pod> -c <container>` |
| **이미지(Image)** | 컨테이너를 만드는 불변 패키지. 레지스트리에서 pull | `image: web-a:1.0`. k3d 는 `k3d image import` 로 노드에 넣음 |
| **Deployment** | 같은 Pod 를 N 개 유지하고, 이미지를 바꿀 때 순차 교체(롤링 업데이트)하는 리소스 | 웹·WAS 같은 무상태 앱의 표준. `kubectl rollout status` |
| **ReplicaSet** | Deployment 가 내부적으로 만드는 "Pod N 개 유지" 리소스 | 직접 다룰 일 거의 없음. 롤백 시 이전 ReplicaSet 으로 되돌림 |
| **replica** | 같은 Pod 의 복제본 수 | `replicas: 3`. 노드 장애 시 다른 노드에서 다시 채워짐 |
| **StatefulSet** | 순서·고유 이름·고정 스토리지가 필요한 Pod 관리 | DB, Kafka 브로커 같은 상태 있는 앱. Pod 이름이 `kafka-0`, `kafka-1` |
| **DaemonSet** | 모든 노드(또는 선택한 노드)에 Pod 를 정확히 하나씩 | 로그 수집기, 모니터링 에이전트, kube-vip, Longhorn |
| **Job** | 한 번 실행하고 끝나는 작업 | 배치, 마이그레이션. 성공하면 Completed |
| **CronJob** | Job 을 일정 주기로 생성 | 백업, 정리 작업. cron 표기 |
| **롤링 업데이트(Rolling Update)** | 새 Pod 를 하나씩 띄우고 옛 Pod 를 하나씩 내리는 무중단 배포 | Deployment 기본 전략. `maxSurge`, `maxUnavailable` |
| **롤백(Rollback)** | 이전 버전 ReplicaSet 으로 되돌리기 | `kubectl rollout undo deployment/<name>` |
| **init 컨테이너** | 본 컨테이너 전에 순서대로 실행되고 끝나는 컨테이너 | DB 준비 대기, 설정 파일 생성 |
| **사이드카(Sidecar)** | 본 컨테이너와 같은 Pod 에서 함께 도는 보조 컨테이너 | 로그 전송, 프록시 |

## 네트워크

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **Service** | Pod 집합에 고정된 가상 IP 와 DNS 이름을 주는 리소스. Pod 가 죽고 새로 떠도 주소가 안 바뀜 | `selector` 로 Pod 를 고름. Pod 끼리 통신은 Service 이름으로 |
| **ClusterIP** | 클러스터 안에서만 접근되는 Service. 기본 타입 | 내부 통신용. `web → backend` |
| **NodePort** | 모든 노드의 특정 포트(30000~32767)로 외부 노출 | 테스트용. 운영에서는 Ingress 나 LoadBalancer |
| **LoadBalancer** | 외부 LB 를 붙여 노출하는 Service 타입. 구현은 환경마다 다름 | 클라우드는 실제 LB, k3s 는 ServiceLB, RKE2 는 MetalLB 필요. 없으면 `<pending>` |
| **Endpoint / EndpointSlice** | Service 가 실제로 가리키는 Pod IP 목록 | Service 가 503 이면 여기가 비어 있는지 확인 |
| **Ingress** | HTTP/HTTPS 요청을 호스트명·경로 기준으로 Service 에 라우팅하는 규칙 | `a.example.test → web-a`. 규칙만 있고 실행은 Ingress 컨트롤러 |
| **Ingress 컨트롤러** | Ingress 규칙을 실제로 처리하는 프록시 | Traefik(k3s·RKE2 기본), ingress-nginx(2026-03 EOL) |
| **IngressClass** | 어느 Ingress 컨트롤러가 이 Ingress 를 처리할지 지정 | `ingressClassName: traefik`. 항상 명시 |
| **NetworkPolicy** | Pod 간 통신을 허용·차단하는 방화벽 규칙. CNI 가 집행 | 지원 안 하는 CNI 에서는 오류 없이 무시됨. k3s 는 내장 컨트롤러가 집행 |
| **DNS (CoreDNS)** | 클러스터 내부 DNS. Service 이름을 IP 로 | `backend.demo.svc.cluster.local`. 같은 네임스페이스면 `backend` 만으로 |
| **hostNetwork** | Pod 가 노드의 네트워크를 그대로 사용 | kube-vip, 일부 모니터링 에이전트 |
| **VIP(Virtual IP)** | 여러 노드가 나눠 갖는 가상 IP. 한 노드가 죽으면 다른 노드로 이동 | API 고정 접점(kube-vip), Ingress 진입(MetalLB) |

## 설정·저장

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **ConfigMap** | 설정값(키-값, 파일)을 Pod 와 분리해 저장 | 환경변수 또는 파일로 마운트. 이미지 재빌드 없이 설정 변경 |
| **Secret** | 비밀값(비밀번호, 인증서, 토큰) 저장. base64 인코딩이지 암호화 아님 | etcd 에 저장됨. server 노드 보안이 중요한 이유 |
| **Volume** | Pod 안 컨테이너가 쓰는 저장 공간. Pod 수명과 같음 | `emptyDir`, `hostPath`, ConfigMap/Secret 마운트 |
| **PersistentVolume(PV)** | Pod 와 독립된 수명의 저장소. 관리자가 만들거나 자동 생성 | 실제 디스크·NFS·Longhorn 볼륨 |
| **PersistentVolumeClaim(PVC)** | "이만큼의 저장소가 필요하다"는 요청. PV 와 연결(Bound) | 앱은 PVC 만 선언. `kubectl get pvc` 가 Bound 인지 |
| **StorageClass** | PVC 요청 시 PV 를 자동으로 만드는 방법 정의 | `local-path`(k3s 기본), `longhorn`. default 가 없으면 PVC 가 Pending |
| **local-path** | 노드 로컬 디스크에 PV 를 만드는 k3s 내장 provisioner | 데이터가 노드에 묶여 노드 장애 시 Pod 가 못 옮겨감 |
| **Longhorn** | 노드 디스크를 묶어 복제하는 분산 블록 스토리지 | 복제 3 이면 노드 1대 장애에도 볼륨 유지 |

## 스케줄링·자원

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **requests** | Pod 가 최소로 필요한 CPU·메모리. 스케줄러가 이걸 보고 노드를 고름 | 안 적으면 노드가 넘치도록 배치될 수 있음 |
| **limits** | Pod 가 최대로 쓸 수 있는 CPU·메모리. 메모리 초과 시 OOMKilled | 겸임 구성에서 컨트롤 플레인 보호 수단 |
| **taint** | 노드에 붙이는 "이 노드는 Pod 를 받지 않는다" 표시 | `node-role.kubernetes.io/control-plane=:NoSchedule`. k3s 는 기본 없음 |
| **toleration** | taint 가 있는 노드에도 갈 수 있다는 Pod 쪽 허가 | 시스템 DaemonSet 이 컨트롤 플레인에 뜨는 방법 |
| **nodeSelector / affinity** | Pod 를 특정 라벨의 노드에만 배치 | `disk=ssd`, 컨트롤 플레인 전용 |
| **label** | 리소스에 붙이는 키-값 태그. selector 의 기준 | `app: web-a`. Service·Deployment 가 Pod 를 찾는 방법 |
| **annotation** | 도구용 메타데이터. selector 에 안 쓰임 | Ingress 컨트롤러 옵션, cert-manager 설정 |
| **네임스페이스(Namespace)** | 리소스를 논리적으로 나누는 단위. 이름 충돌 방지, 권한·자원 제한 경계 | `kube-system`(시스템), `default`, 앱별 `demo`. `-n` 옵션 |
| **LimitRange / ResourceQuota** | 네임스페이스 단위 기본값·상한 | requests/limits 누락 방지, 팀별 자원 상한 |
| **PriorityClass** | Pod 우선순위. 자원 부족 시 낮은 것부터 축출 | `system-cluster-critical` 이 시스템 컴포넌트 |
| **축출(Eviction)** | 노드 자원 부족 시 kubelet 이 Pod 를 내보내는 것 | 메모리 압박 시 requests 없는 Pod 부터 |
| **drain / cordon** | 노드에서 Pod 를 비우기 / 새 Pod 배치 막기 | 노드 점검·업그레이드 전 `kubectl drain <node>` |

## 상태·진단

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **Ready** | 노드 또는 Pod 가 정상 동작 중 | `NotReady` 노드는 5분 뒤 Pod 가 다른 노드로 |
| **Pending** | Pod 가 아직 노드에 배치되지 않음 | 자원 부족, PVC 미바인딩, taint. `kubectl describe pod` |
| **CrashLoopBackOff** | 컨테이너가 시작 직후 계속 죽어 재시작 간격이 늘어나는 상태 | 앱 오류, 설정 누락. `kubectl logs --previous` |
| **ImagePullBackOff** | 이미지를 못 받아옴 | 태그 오타, 레지스트리 인증, k3d 는 import 누락 |
| **OOMKilled** | 메모리 limits 초과로 강제 종료 | limits 상향 또는 메모리 누수 확인 |
| **liveness probe** | "살아 있나" 검사. 실패하면 컨테이너 재시작 | 데드락 감지 |
| **readiness probe** | "요청 받을 준비 됐나" 검사. 실패하면 Service 에서 제외 | 기동 중·과부하 시 트래픽 차단 |
| **startup probe** | 기동이 느린 앱을 위해 liveness 검사를 미룸 | JVM 앱 |
| **rollout** | Deployment 의 배포 진행 | `kubectl rollout status/history/undo` |
| **describe** | 리소스 상세와 최근 이벤트 | 문제 원인 1순위 확인 명령 |
| **이벤트(Event)** | 클러스터에서 일어난 일의 기록 | `kubectl get events --sort-by=.lastTimestamp` |

## 배포 도구·확장

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **매니페스트(Manifest)** | 리소스를 정의한 YAML 파일 | `kubectl apply -f k8s.yaml` |
| **선언형(Declarative)** | "이렇게 되어야 한다"를 적으면 Kubernetes 가 맞춰 가는 방식 | apply 를 여러 번 해도 결과 같음 |
| **Helm** | 여러 매니페스트를 템플릿으로 묶은 "차트"를 설치·업그레이드하는 도구 | cert-manager, Rancher, MetalLB, Longhorn 설치 |
| **차트(Chart)** | Helm 패키지. values 로 값을 바꿔 설치 | `helm install rancher rancher-stable/rancher --set hostname=...` |
| **HelmChart (k3s/RKE2)** | 매니페스트 디렉터리에 두면 내장 helm-controller 가 차트를 설치하는 리소스 | `/var/lib/rancher/rke2/server/manifests/` |
| **CRD(Custom Resource Definition)** | Kubernetes 에 새 리소스 종류를 추가 | MetalLB 의 `IPAddressPool`, cert-manager 의 `Certificate` |
| **Operator** | CRD + 그것을 관리하는 컨트롤러. 앱 운영 지식을 자동화 | Strimzi(Kafka), Longhorn |
| **RBAC** | 누가(User/ServiceAccount) 무엇을(리소스) 어떻게(동사) 할 수 있는지 | Role, ClusterRole, RoleBinding |
| **ServiceAccount** | Pod 가 API 서버에 접근할 때 쓰는 계정 | 기본 토큰 자동 마운트는 CIS 에서 끔 |
| **Pod Security Admission(PSA)** | Pod 보안 수준을 네임스페이스 단위로 강제 | `privileged` / `baseline` / `restricted`. RKE2 CIS 프로파일은 restricted |
| **securityContext** | Pod·컨테이너의 실행 권한 설정 | non-root, capabilities drop, seccomp. restricted 통과 조건 |
| **Rancher** | 여러 클러스터를 UI 로 관리하는 플랫폼 | 클러스터 생성·업그레이드·RBAC. 자체도 클러스터 위에 설치 |

## Rancher·배포 실무 (온프레미스)

실서버 MGMT·DEV 클러스터를 만들고 앱을 옮기며 나온 용어. 절차는 `rancher/` 아래 1~5번 노트에 있다.

### 클러스터·Rancher

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **MGMT 클러스터** | Rancher 자체가 올라가는 클러스터. 앱은 올리지 않는다 | 노드 3대, Rancher 3 replica |
| **다운스트림 클러스터** | Rancher가 만들고 관리하는 업무용 클러스터 | DEV, 나중에 stage·prod |
| **Custom 클러스터** | Rancher가 서버에 등록 명령을 실행시켜 RKE2를 설치하는 방식 | Registration 명령 → rancher-system-agent → rke2-server |
| **rancher-system-agent** | 노드에서 Rancher가 내린 설치 계획(plan)을 실행하는 에이전트 | 등록 직후 설치. RKE2 설치·업그레이드를 맡음 |
| **cattle-cluster-agent** | 다운스트림 클러스터 안에서 Rancher와 연결을 유지하는 Pod | 이 Pod가 떠야 Rancher 화면에 클러스터가 Active |
| **Edit Config** | Rancher 화면에서 클러스터 설정을 바꾸는 곳 | 노드의 `config.yaml.d/50-rancher.yaml`, `registries.yaml`은 Rancher가 덮어써서 직접 고치지 않음 |
| **Additional Manifest** | Edit Config 안의 칸. 여기 넣은 YAML을 Rancher가 클러스터에 적용·유지 | Traefik HelmChartConfig. 개인키 Secret은 넣지 않음 (평문 저장) |
| **Registries (미러)** | 노드 containerd가 이미지를 받을 때 다른 레지스트리를 먼저 보게 하는 설정 | `docker.io` → Nexus. 미러에 없으면 원래 주소로 |
| **Project (Rancher)** | 네임스페이스 여러 개를 묶어 권한을 주는 Rancher 단위 | System 프로젝트 = 시스템 구성요소, Default = 앱 |
| **Apps (Rancher)** | Helm 차트를 화면에서 설치·업그레이드·롤백하는 메뉴 | Repositories → Charts → Installed Apps |
| **tar 설치** | RPM 대신 RKE2 바이너리 묶음을 풀어 설치하는 방식 | `/usr/local/bin/rke2`. `rpm -q`에 안 나오는 것이 정상 |
| **bind mount** | 한 폴더를 다른 경로에 그대로 붙여 보이게 하는 것 | `/app/rke2/log-pods` = `/var/log/pods` |

### 외부 접속

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **MetalLB** | L4 장비가 없는 곳에서 LoadBalancer Service에 IP를 주는 구현 | DEV VIP. `IPAddressPool`, `L2Advertisement` |
| **L2 모드** | 같은 대역의 빈 IP를 ARP로 알리는 방식. 한 번에 노드 하나만 응답 | VIP를 가진 노드로 모든 요청이 먼저 들어옴. 그 노드 부하가 높게 보일 수 있음 |
| **HelmChartConfig** | RKE2 내장 차트(Traefik 등)에 values를 덧붙이는 리소스 | `rke2-traefik`. 키는 `service.spec.type` (일반 Traefik 차트와 다름) |
| **TLSStore** | Traefik이 쓰는 인증서 모음. `defaultCertificate` 하나 + `certificates` 목록 | 와일드카드 인증서를 앱마다 넣지 않고 한 곳에 |
| **SNI** | TLS 연결 처음에 클라이언트가 접속할 도메인을 알리는 값 | Traefik이 도메인별 인증서를 고르는 근거. nginx `proxy_ssl_server_name on` |
| **TLS 종료(termination)** | 앞단이 HTTPS를 풀고 뒤로는 HTTP로 넘기는 것 | Traefik이 종료. 앱 nginx는 80만 염 |
| **externalTrafficPolicy: Local** | 요청을 받은 노드의 Pod로만 보내 사용자 IP를 보존 | Traefik Service |
| **X-Forwarded-For / real_ip** | 프록시를 거쳐도 원래 사용자 IP를 전하는 헤더 / nginx가 그 값을 `$remote_addr`로 쓰는 설정 | `set_real_ip_from <Pod 대역>` |

### 빌드·차트

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **멀티 스테이지 빌드** | 빌드용 이미지에서 결과만 최종 이미지로 복사하는 Dockerfile 작성법 | 최종 이미지에 node_modules·Gradle이 없음 |
| **빌드 컨텍스트** | `docker build`가 이미지 안으로 복사할 수 있는 폴더 | 저장소 루트. `-f deploy/k8s/Dockerfile .` |
| **`<이름>.dockerignore`** | 특정 Dockerfile 빌드에만 쓰는 ignore 파일 (BuildKit) | `Dockerfile.dockerignore`. 루트 `.dockerignore`는 그대로 |
| **Nexus hosted 저장소** | Nexus에 직접 올린 것을 보관하는 저장소 | docker-hosted(이미지), helm-hosted(차트) |
| **릴리스 (Helm)** | 클러스터에 설치된 차트 한 벌. 이름과 네임스페이스가 정해짐 | 네임스페이스를 옮길 수 없음 → 지우고 재설치 |
| **리비전 (Helm)** | 릴리스를 설치·업그레이드할 때마다 늘어나는 번호 | Rollback 대상 |
| **values** | 차트 템플릿에 넣는 설정 값 | `profiles`, `overrides`, `environment` |
| **appVersion** | 차트가 배포하는 앱의 버전 | 이미지 태그 기본값. 차트 버전과 같게 `1.0.N` |
| **profiles / overrides** | 환경별 설정 묶음 / 급할 때 화면에서 덮어쓰는 칸 (이 프로젝트의 차트 규칙) | Rancher Upgrade 화면 |
| **builtFor** | 이 차트를 빌드한 환경. 이미지 경로 앞부분이자 설치 환경 잠금 (이 프로젝트의 차트 규칙) | Jenkins가 채움. `environment`와 다르면 설치 실패 |
| **Server-Side Apply / field manager** | 리소스 필드마다 누가 썼는지(주인)를 기록하는 방식. 다른 주인이 쓴 필드를 덮으면 충돌 | Rancher에서 Scale 후 Helm Upgrade → `conflict with "agent"` |

### 앱 실행

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **hostAliases** | Pod의 `/etc/hosts`에 이름 → IP를 넣는 설정 | `docker run --add-host` 대신. Java는 따르고 nginx 변수 proxy_pass는 따르지 않음 |
| **Service FQDN** | `<서비스>.<네임스페이스>.svc.cluster.local` 형태의 전체 이름 | 웹 nginx → WAS. 변수 proxy_pass는 짧은 이름을 못 찾음 |
| **envsubst (nginx 템플릿)** | nginx 공식 이미지가 시작할 때 `templates/*.template`의 `${변수}`를 환경변수로 바꾸는 기능 | 백엔드 주소를 이미지 밖(values)에서 넣음 |
| **resolver (nginx)** | nginx가 요청 시점에 이름을 찾을 DNS 서버 | 변수 proxy_pass에 필요. Pod의 `/etc/resolv.conf`에서 읽음 |
| **relaxed binding (Spring)** | 환경변수 `TXM_URL`이 설정 `txm.url`을 덮어쓰는 Spring 규칙 | 차트 `profiles.<env>.env` |
| **emptyDir** | Pod가 살아 있는 동안만 있는 임시 볼륨 | WAS `/app/logs`. Pod와 함께 사라짐 |
| **tcpSocket 프로브** | 포트가 열렸는지로 준비·생존을 판단하는 검사 | 헬스 URL이 없는 WAS |
| **CrashLoopBackOff** | 컨테이너가 계속 죽어 재시작 간격이 늘어나는 상태 (최대 5분) | 횟수 제한은 없음. 멈추려면 replicas 0 |

### 로그

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **`/var/log/pods`** | kubelet이 컨테이너 stdout을 파일로 남기는 곳 | `<ns>_<pod>_<uid>/<컨테이너>/0.log`. 숫자는 재시작 횟수 |
| **Rancher Logging** | 로그를 다른 저장소로 보내는 Rancher 차트 (Logging Operator) | 보내기만 함. 받을 곳이 따로 필요 |
| **Fluent Bit** | 노드의 로그 파일을 읽어 넘기는 가벼운 수집기 | Rancher Logging이 노드마다 띄움 |
| **ClusterFlow / ClusterOutput** | 어떤 로그를 보낼지 / 어디로 보낼지 정하는 Logging 리소스 | `cattle-logging-system` |
| **Loki** | 로그를 라벨로 묶어 저장하는 서버. 본문 전체를 색인하지 않아 가벼움 | Grafana로 조회. 클러스터 밖 VM 예정 |
| **stern** | 여러 Pod 로그를 한 화면에 이어 보여 주는 CLI | 개발자 PC + kubeconfig |
| **k9s** | 터미널용 쿠버네티스 관리 화면 | Pod 선택 → `l` 로그 |

## kind 목록 (매니페스트의 `kind:`)

`kind` 는 "어떤 종류의 리소스인가", `apiVersion` 은 "그 kind 가 속한 API 그룹/버전". 둘은 짝이 정해져 있음 (`kind: Deployment` 에 `apiVersion: v1` 은 오류).

### 기본 리소스

| 분류 | kind | apiVersion |
| --- | --- | --- |
| 워크로드 | `Pod` | `v1` |
| | `Deployment`, `ReplicaSet`, `StatefulSet`, `DaemonSet` | `apps/v1` |
| | `Job`, `CronJob` | `batch/v1` |
| 네트워크 | `Service` | `v1` |
| | `Ingress`, `IngressClass`, `NetworkPolicy` | `networking.k8s.io/v1` |
| | `EndpointSlice` | `discovery.k8s.io/v1` |
| 설정·저장 | `ConfigMap`, `Secret`, `PersistentVolume`, `PersistentVolumeClaim` | `v1` |
| | `StorageClass` | `storage.k8s.io/v1` |
| 구조·자원 | `Namespace`, `Node`, `LimitRange`, `ResourceQuota` | `v1` |
| | `PriorityClass` | `scheduling.k8s.io/v1` |
| | `HorizontalPodAutoscaler` | `autoscaling/v2` |
| 권한 | `ServiceAccount` | `v1` |
| | `Role`, `ClusterRole`, `RoleBinding`, `ClusterRoleBinding` | `rbac.authorization.k8s.io/v1` |
| 확장 | `CustomResourceDefinition` | `apiextensions.k8s.io/v1` |

핵심 리소스는 그룹 없이 `v1`, 나머지는 `그룹/버전`.

### CRD 로 추가되는 kind (설치한 도구가 등록)

| 도구 | kind | apiVersion |
| --- | --- | --- |
| k3s·RKE2 helm-controller | `HelmChart`, `HelmChartConfig` | `helm.cattle.io/v1` |
| MetalLB | `IPAddressPool`, `L2Advertisement` | `metallb.io/v1beta1` |
| cert-manager | `Certificate`, `Issuer`, `ClusterIssuer` | `cert-manager.io/v1` |
| Traefik | `IngressRoute`, `Middleware`, `TLSStore` | `traefik.io/v1alpha1` |
| Rancher Logging | `ClusterFlow`, `ClusterOutput`, `Flow`, `Output` | `logging.banzaicloud.io/v1beta1` |
| Longhorn | `Volume`, `Node` 등 | `longhorn.io/v1beta2` |

### k3d 설정 파일의 kind (클러스터에 apply 하는 것이 아님)

| kind | apiVersion | 용도 |
| --- | --- | --- |
| `Simple` | `k3d.io/v1alpha5` | `k3d cluster create` 옵션을 YAML 로 옮긴 형식. 유일한 종류 |

`apiVersion` / `kind` / `metadata.name` 세 줄은 Kubernetes 매니페스트와 같은 관례. 내용이 아니라 "파일의 신분증" 이라 항상 그대로 복사.

### 실제 목록은 클러스터에 물어본다

```bash
kubectl api-resources                    # 현재 클러스터의 모든 kind, 약칭(NAME/SHORTNAMES), apiVersion
kubectl api-resources --namespaced=false # 네임스페이스에 속하지 않는 것 (Node, PV, StorageClass, ClusterRole ...)
kubectl explain deployment               # 특정 kind 의 필드 설명
kubectl explain deployment.spec.strategy # 하위 필드
```

## 로컬 실습 (k3d)

| 용어 | 정의 | 만나는 지점 |
| --- | --- | --- |
| **k3s** | 경량 Kubernetes 배포판. 단일 바이너리, SQLite 기본, Traefik·ServiceLB·local-path 내장 | 실서버 개발 환경 |
| **k3d** | k3s 를 Docker 컨테이너로 띄우는 도구. 노드 1개 = 컨테이너 1개 | 로컬 실습 |
| **serverlb** | k3d 가 만드는 nginx 컨테이너. 호스트 포트를 노드로 전달하고 API 를 server 들에 분산 | 실서버의 kube-vip/LB 역할. `docker port k3d-lab-serverlb` |
| **image import** | 호스트 Docker 이미지를 노드 containerd 로 복사 | 로컬 빌드 이미지를 쓰는 방법. 없으면 ImagePullBackOff |
| **Traefik** | k3s·RKE2 기본 Ingress 컨트롤러 | `kube-system` 의 Pod. Ingress 규칙을 실제로 처리 |
| **ServiceLB(klipper-lb)** | k3s 내장 LoadBalancer 구현. 노드 포트를 hostPort 로 여는 방식 | RKE2 에는 없음 |
