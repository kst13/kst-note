# DEV 클러스터 설치 — Rancher Custom 클러스터 (RKE2)

[2. 설치](2.%20설치.md)로 MGMT 3대와 Rancher를 올린 뒤 진행한다. DEV 서버 3대를 Rancher의 Custom 클러스터로 등록한다. 서버 IP는 [2. 설치](2.%20설치.md) 0.1 표를 따른다.

## 0. MGMT 설치와 다른 점

**DEV에는 RKE2를 직접 설치하지 않는다.** Rancher 화면에서 클러스터를 만들면 등록 명령이 나온다. 그 명령을 DEV 서버에서 실행하면 Rancher가 RKE2를 설치한다.

| 구분 | MGMT | DEV |
|---|---|---|
| OS 사전 작업 | [1. 설치 선행](1.%20%20설치%20선행.md) | **같음** |
| RKE2 설치 | tar 반입 후 직접 설치 | Rancher가 자동 설치 |
| config.yaml | `/etc/rancher/rke2/config.yaml` 직접 작성 | Rancher가 `/etc/rancher/rke2/config.yaml.d/50-rancher.yaml` 작성 |
| 클러스터 토큰 | MGMT-1이 만들고 직접 복사 | Rancher가 만들고 전달 |
| Traefik 설정 | HelmChartConfig 직접 작성 | 하지 않음 |
| Helm, Rancher 차트 | 설치 | 하지 않음 |

MGMT의 config, 토큰, Traefik 설정을 DEV에 복사하지 않는다. 복사하면 DEV가 MGMT 클러스터에 붙으려 한다.

### 등록 명령이 설치하는 것

| 순서 | 설치되는 것 | 누가 설치 | 역할 |
|---|---|---|---|
| 1 | `rancher-system-agent` 서비스 | 등록 명령 | Rancher에서 plan(이 노드에서 실행할 작업 목록)을 받아 실행 |
| 2 | RKE2 (`rke2-server` 서비스) | system-agent가 installer 이미지로 설치 | 쿠버네티스 본체. etcd, apiserver, kubelet, containerd, canal, CoreDNS, Traefik |
| 3 | `cattle-cluster-agent`, `fleet-agent` 등 Pod | Rancher가 클러스터에 배포 | Rancher UI와 배포 통로 |

RKE2가 곧 쿠버네티스다. 버전 `v1.36.5+rke2r1`은 쿠버네티스 1.36.5를 RKE2로 묶은 첫 빌드라는 뜻이다.

역할(Node Role)에 따라 서비스가 다르다.

| 고른 역할 | 서비스 |
|---|---|
| etcd 또는 Control Plane 포함 | `rke2-server` |
| Worker만 | `rke2-agent` |

이번 설치는 3대 모두 etcd + Control Plane + Worker라서 3대 모두 `rke2-server`다.

### Docker와 Jenkins

DEV 서버의 Docker는 끈다. Docker가 남기는 iptables 규칙(FORWARD DROP)이 RKE2 네트워크와 충돌한다. Jenkins가 빌드한 앱은 Docker 없이 실행된다.

| 서버 | Docker | 하는 일 |
|---|---|---|
| Jenkins | 필요 | 이미지 빌드, Nexus push |
| Nexus | - | 이미지·차트 보관 |
| DEV 노드 | **끔** | RKE2 containerd가 Nexus에서 이미지를 받아 실행 |

DEV 서버에서 `docker run`이나 compose로 돌던 서비스가 있으면 Docker를 끄기 전에 옮길 곳을 정한다.

```bash
# 비어 있어야 Docker를 끌 수 있음
sudo docker ps --format '{{.Names}}\t{{.Image}}\t{{.Status}}'
```

## 1. DEV 3대: OS 사전 작업

[1. 설치 선행](1.%20%20설치%20선행.md) 1.1~1.7을 MGMT와 같이 진행한다.

- swap은 1.4의 DEV 기준을 따른다. swap을 남기면 4단계에서 kubelet 옵션을 넣는다.
- Docker를 끈 뒤 재부팅한다. 재부팅 뒤 `ip link show docker0`이 "does not exist", `sudo iptables -S FORWARD | head -1`이 `-P FORWARD ACCEPT`여야 한다.
- EPEL을 끈다. `sudo dnf config-manager --set-disabled epel epel-cisco-openh264`
- `/app` bind mount는 **5단계 등록 명령 전에** 건다. RKE2가 설치된 뒤에는 새로 걸지 않는다.

`scripts/01-prepare.sh`는 DEV에서 쓸 수 없다. 노드 번호를 MGMT IP로 검사해서 멈춘다.

## 2. DEV 3대: 접속 확인

```bash
# L4 VIP가 나와야 함
getent hosts rancher.<도메인>
# -k 없이 pong. 공인 인증서라 DEV에 CA를 넣을 필요 없음
curl -s https://rancher.<도메인>/ping; echo
# 401이면 Docker Hub 접속 정상, 000이면 차단

```

`pong`이 안 나오면 DEV → MGMT·VIP 443 방화벽을 확인한다. 이름 풀이가 안 되면 DNS 등록이나 `/etc/hosts`로 해결한다.

## 3. DEV 3대: RKE2 이미지 묶음 미리 넣기

Docker Hub의 큰 이미지는 CDN(`production.cloudfront.docker.com`)에서 끊길 수 있다. RKE2는 기동할 때 `/var/lib/rancher/rke2/agent/images/`의 묶음을 먼저 불러온다. 묶음을 넣어 두면 RKE2 구성요소 16개를 받지 않는다.

**묶음 버전은 4단계에서 고를 Kubernetes Version과 같아야 한다.** Rancher 2.15.2 화면의 최저 버전은 `v1.36.5+rke2r1`이었다. MGMT용 1.36.4 묶음은 쓸 수 없다. DEV가 MGMT보다 높아도 된다. 두 클러스터 버전은 독립이다.

PC에서 받는다. DEV는 GitHub 방화벽이 없다.

```powershell
cd $HOME\Downloads
curl.exe -fLO "https://github.com/rancher/rke2/releases/download/v1.36.5%2Brke2r1/rke2-images.linux-amd64.tar.zst"
curl.exe -fLO "https://github.com/rancher/rke2/releases/download/v1.36.5%2Brke2r1/sha256sum-amd64.txt"
foreach ($ip in "<DEV-1 IP>","<DEV-2 IP>","<DEV-3 IP>") {
  scp rke2-images.linux-amd64.tar.zst sha256sum-amd64.txt "<계정>@${ip}:~/"
}
```

DEV 3대 각각에서 검증하고 넣는다. `/tmp` 대신 홈에 받아도 된다. Rocky 9는 `/tmp`를 정리할 수 있어 홈이 더 안전하다.

```bash
cd ~
# OK여야 다음으로 진행
grep 'rke2-images.linux-amd64.tar.zst$' sha256sum-amd64.txt | sha256sum -c -
sudo install -d /var/lib/rancher/rke2/agent/images
sudo mv ~/rke2-images.linux-amd64.tar.zst /var/lib/rancher/rke2/agent/images/
# 체크섬 파일은 남겨도 됨. 단 images 폴더에는 넣지 않음. RKE2가 이미지로 읽으려 함
ls -lZ /var/lib/rancher/rke2/agent/images/
```

- `mv`는 원래 SELinux 라벨을 가져간다. `user_home_t`가 보이면 `sudo restorecon -Rv /var/lib/rancher/rke2/agent/images/`를 실행한다. SELinux가 `Disabled`면 라벨이 `?`로 보이며 무시한다.
- SELinux가 `Enforcing`/`Permissive`면 MGMT 반입 묶음의 `rke2-selinux` RPM도 미리 설치한다. `sudo dnf --disablerepo='*' --enablerepo=baseos,appstream install -y ~/rke2-selinux-0.23-1.el9.noarch.rpm`

## 4. Rancher 화면: 클러스터 만들기

☰ → **Cluster Management** → **Create** → **Custom**

| 메뉴 | 설정 |
|---|---|
| Basics | Cluster Name `dev`, Kubernetes Version `v1.36.5+rke2r1`, Container Network **`canal`** |
| Advanced | swap을 남긴 경우만 Additional Kubelet Args에 `fail-swap-on=false` |
| Networking | 기본값. Pod `10.42.0.0/16`, Service `10.43.0.0/16`이 사내 대역과 겹치지 않는지만 확인 |
| Registries | 비워 둠. 클러스터가 Active된 뒤 8단계에서 넣음 |
| 나머지 | 기본값 (Member Roles, Add-on, Additional Manifest, Agent Environment Vars, Cluster Agent, etcd, Fleet Agent, Labels, Upgrade Strategy) |

- **Container Network:** Rancher 기본값은 Calico다. MGMT와 같은 canal로 바꾼다. 문서의 점검 항목(UDP 8472)도 canal 기준이다. Calico로 두면 노드 사이 UDP 4789가 필요하다.
- **Networking 대역:** 클러스터를 만든 뒤에는 바꿀 수 없다.
- **etcd:** 기본값은 5시간마다 자동 snapshot, 5개 보관이다.
- **`fail-swap-on=false`:** 앞에 `--`를 붙이지 않는다. Machine Selector 안이 아니라 맨 위 기본 항목에 넣는다. swap이 켜져 있는데 빠지면 kubelet이 뜨지 않는다. swap 사용 방식은 1.4의 `90-swap.conf`(`LimitedSwap`)가 정한다.

**Create**를 누른다.

## 5. DEV: 등록 명령 실행

Registration 탭에서 고른다.

| 항목 | 값 |
|---|---|
| Node Role | etcd, Control Plane, Worker 모두 체크 |
| Node Name (Show Advanced) | 노드마다 `dev-1`, `dev-2`, `dev-3` |
| Node Public IP | 비움. NAT·클라우드처럼 외부 IP가 따로 있을 때만 씀 |
| Node Private IP | NIC가 하나면 비움. 여러 개면 노드의 업무망 IP |
| Insecure | 체크하지 않음. 공인 인증서라 필요 없음 |

NIC 개수는 `ip -4 -o addr show scope global | awk '{print $2, $4}'`로 본다. IP가 여러 개인데 비우면 엉뚱한 NIC로 등록되어 Pod 통신이 안 될 수 있다.

명령에는 클러스터 등록 토큰이 들어 있다. 채팅·문서에 붙이지 않는다. `--node-name`(Private IP를 넣었다면 `--internal-address`도)만 노드마다 바꿔 실행한다.

1. DEV-1에서 먼저 실행한다.
2. Rancher 화면에 dev-1이 나타나 진행되면 DEV-2·3에서 실행한다. 둘은 동시에 해도 된다. Rancher가 etcd에 한 대씩 붙인다.

### 정상 출력

```text
[INFO]  CA strict verification is set to false
[INFO]  Successfully tested Rancher connection
[ERROR]  401 received while downloading Rancher connection information. Sleeping for 5 seconds and trying again
...
[INFO]  Successfully downloaded and validated Rancher connection information
[INFO]  Starting/restarting rancher-system-agent.service
```

| 메시지 | 의미 |
|---|---|
| `CA strict verification is set to false` | Rancher를 `agentTLSMode: system-store`로 설치해서 정상. OS CA 목록으로 공인 인증서를 검증 |
| `401 received ... trying again` 몇 번 | 정상. 등록 직후 Rancher가 이 노드의 객체와 plan을 만드는 동안 401을 준다 |
| `Starting/restarting rancher-system-agent.service` | 등록 성공. 여기서부터 RKE2 설치가 자동 진행 |

## 6. 진행 확인

```bash
# 등록·설치 단계
sudo journalctl -u rancher-system-agent -f
# RKE2 설치 뒤
sudo journalctl -u rke2-server -f
```

브라우저: Cluster Management → `dev` → Machines 탭. 클러스터 상태 옆 메시지가 Rancher가 기다리는 것을 가장 정확하게 보여 준다.

**첫 노드는 15분쯤 걸린다.** 실제 설치(DEV-1)의 순서다.

| 시각 | 일 |
|---|---|
| 16:41 | 등록, `etcd.yaml`·`kube-proxy.yaml` 생성, 이미지 묶음 16개 불러옴 (19초) |
| 16:42 | `kube-apiserver.yaml` 생성 |
| 16:42~16:51 | `runtime core not ready` 반복. Rancher 메시지 `Waiting for Cluster control plane to be initialized` |
| 16:51 | `kube-controller-manager.yaml`, `kube-scheduler.yaml`, `cloud-controller-manager.yaml` 생성 |
| 16:52 | canal, CoreDNS, Traefik, metrics-server 기동. `cattle-cluster-agent`는 배치 후 이미지 받기 시작 |

Rancher는 etcd와 apiserver를 확인한 뒤 나머지 control plane을 내려보낸다. 그 사이 9분 대기는 정상이었다. DEV-2·3은 더 빠르다. 기다리는 동안 다음으로 어디까지 왔는지 본다.

```bash
# 생성된 static pod 파일과 시각
sudo ls -l /var/lib/rancher/rke2/agent/pod-manifests/
S=unix:///run/k3s/containerd/containerd.sock
sudo /var/lib/rancher/rke2/bin/crictl -r $S pods
```

### 무시해도 되는 메시지

| 로그 | 의미 |
|---|---|
| system-agent: `secret received was too old, requeuing` | plan이 빠르게 바뀌어 이전 버전 알림을 버린 것 |
| system-agent: `updated plan secret ... with feedback` (15초마다) | plan 실행 결과와 상태 점검을 Rancher에 보고 중. 좋은 신호 |
| rke2: `containerd.sock: no such file`, `/readyz ... connection refused` | 기동 직후 잠깐 |
| rke2: `Failed to list nodes with etcd role: runtime core not ready` | apiserver 준비 전. 첫 노드에서 10분 안팎 |
| `cattle-cluster-agent` Event `FailedScheduling ... untolerated taint` | 노드가 막 올라왔을 때 붙는 임시 taint. 곧 `Scheduled` |
| `get nodes`의 ROLES가 처음에 `control-plane,etcd`만 | worker 라벨은 cluster agent 연결 뒤에 붙는다. `Taints: <none>`이면 정상 |
| `helm-install-rke2-*` Pod가 `NotReady`/`Completed` | 애드온을 한 번 설치하고 끝나는 Job |

### 확인이 필요한 경우

| 증상 | 확인 |
|---|---|
| `Waiting to register`에서 멈춤 | DEV → VIP 443, 이름 풀이 |
| `runtime core not ready`가 20분 넘게 | `pod-manifests/`, `crictl pods`, `/var/lib/rancher/rke2/agent/logs/kubelet.log`. swap이 켜져 있는데 `fail-swap-on=false`가 빠졌는지 (`journalctl -u rke2-server | grep 'Running kubelet'`에 옵션이 보임) |
| kubelet.log에 `x509`, `certificate` | 시간 동기화. `chronyc tracking` |
| `ImagePullBackOff` | 9단계 |
| 노드는 Ready인데 Pod끼리 통신 안 됨 | DEV 사이 UDP 8472 |

## 7. 완료 확인

DEV-1에서 확인한다. 평소에는 Rancher → `dev` → Kubectl Shell이나 내려받은 kubeconfig를 쓴다.

```bash
K="sudo /var/lib/rancher/rke2/bin/kubectl --kubeconfig /etc/rancher/rke2/rke2.yaml"
# 3대 Ready, ROLES control-plane,etcd,worker
$K get nodes -o wide
# etcd 3개
$K -n kube-system get pods -l component=etcd -o wide
# 헤더만 나와야 함
$K get pods -A | grep -vE 'Running|Completed'
# 3대 모두 Taints: <none>
$K describe nodes | grep -E '^Name:|^Taints:'
```

브라우저에서 `dev`가 **Active**, Machines 3대가 **Running**이면 끝이다.

## 8. Nexus 연결 (Jenkins 이미지 실행용)

`dev` ⋮ → **Edit Config** → **Registries**

| 항목 | 값 |
|---|---|
| `Enable cluster scoped container registry for Rancher system container images` | **체크하지 않음** |
| Mirrors → Registry Hostname | `<NEXUS_HOST>:5000` |
| Mirrors → Mirror Endpoints | `http://<NEXUS_HOST>:5000` |
| Rewrites | 비움 |
| Registry Authentication → Registry Hostname | `<NEXUS_HOST>:5000` (Mirrors와 같게) |
| Authentication | Create a HTTP Basic Auth Secret → Nexus **읽기 전용** 계정 |
| TLS Secret, CA Cert Bundle | 비움 (HTTP) |

- **맨 위 체크박스:** 켜면 Rancher 시스템 이미지까지 Nexus에서 받으려 한다. `docker-hosted`에는 그 이미지가 없어 업그레이드·노드 추가가 실패한다.
- **`http://`:** 빠지면 containerd가 HTTPS로 접속한다.
- **`docker.io`:** Hostname에 넣지 않는다. 시스템 이미지는 지금처럼 docker.io에서 받는다.
- **계정:** Jenkins push 계정과 분리한다. 노드에는 pull 권한만 필요하다.

**Save**를 누르면 Rancher가 노드마다 `/etc/rancher/rke2/registries.yaml`을 쓰고 `rke2-server`를 한 대씩 재시작한다. 상태가 Updating → Active로 돌아오면 반영이 끝난 것이다. Save 전에 확인하면 파일이 없거나 비어 있다.

```bash
# 비밀번호 줄은 빼고 확인. mirrors에 http:// endpoint가 보여야 함
sudo grep -vE 'password|auth:' /etc/rancher/rke2/registries.yaml
# 저장소 목록과 태그. 계정만 넣으면 비밀번호를 물어봄
curl -s -u '<읽기계정>' http://<NEXUS_HOST>:5000/v2/_catalog; echo
curl -s -u '<읽기계정>' http://<NEXUS_HOST>:5000/v2/test/nginx/tags/list; echo
S=unix:///run/k3s/containerd/containerd.sock
sudo /var/lib/rancher/rke2/bin/crictl -r $S pull <NEXUS_HOST>:5000/test/nginx:<태그>
```

| pull 결과 | 원인 |
|---|---|
| 이미지 ID 출력 | 성공 |
| `401 Unauthorized` | 계정 또는 Authentication의 Hostname 오타 |
| `http: server gave HTTP response to HTTPS client` | Endpoint에 `http://` 누락 |
| `not found` | 이미지 이름·태그 오타 |

### 이미지 이름 쓰는 법

`<NEXUS_HOST>:5000/<catalog 이름>:<태그>`. 예: `<NEXUS_HOST>:5000/test/nginx:latest`

- `test/nginx`처럼 catalog에 나온 경로를 그대로 쓴다.
- Nexus 저장소 이름 `docker-hosted`는 넣지 않는다. 5000 포트가 그 저장소로 연결돼 있다.
- 노드가 인증을 처리하므로 `imagePullSecrets`는 필요 없다.

3대 모두 받는지 보려면 Deployment로 시험한다.

```bash
$K create deployment nexus-test --image=<NEXUS_HOST>:5000/test/nginx:<태그> --replicas=3
$K get pods -l app=nexus-test -o wide
$K delete deployment nexus-test
```

## 9. 이미지 받기가 막힐 때

RKE2 이미지 묶음에 없는 큰 이미지는 docker.io에서 받는다. 대표적으로 `rancher/rancher-agent:v2.15.2`(`cattle-cluster-agent`)다. 실제 설치에서 DEV-1은 결국 받았다.

받는 중인지 멈췄는지는 받는 중인 임시 파일 크기로 본다.

```bash
D=/var/lib/rancher/rke2/agent/containerd/io.containerd.content.v1.content/ingest
# 크기가 늘면 받는 중
sudo du -sh $D; sleep 30; sudo du -sh $D
```

`ErrImagePull`/`ImagePullBackOff`도 kubelet이 계속 다시 시도한다. 계속 실패하면 이미 받은 노드에서 옮긴다. **MGMT에는 `rancher-agent`가 없다.** MGMT는 Rancher가 있는 local 클러스터라 `cattle-cluster-agent`를 쓰지 않는다. 받은 DEV 노드에서 옮긴다. 절차는 [2. 설치](2.%20설치.md) 부록A.4와 같다.

```bash
# 받은 노드
ctr() { sudo /var/lib/rancher/rke2/bin/ctr -a /run/k3s/containerd/containerd.sock -n k8s.io "$@"; }
ctr images export --platform linux/amd64 ~/rancher-agent.tar docker.io/rancher/rancher-agent:v2.15.2
sudo chown "$USER" ~/rancher-agent.tar
scp ~/rancher-agent.tar <계정>@<DEV-2 IP>:~/
# 받을 노드. ctr은 RKE2가 설치된 뒤에만 있음
ctr images import --platform linux/amd64 ~/rancher-agent.tar && rm -f ~/rancher-agent.tar
# 실패한 Pod를 다시 만듦
$K -n cattle-system delete pod -l app=cattle-cluster-agent
```

근본 해결은 `production.cloudfront.docker.com` 방화벽 허용이다. [1. 설치 선행](1.%20%20설치%20선행.md) 1.1 표를 본다.

## 10. 운영 메모

- **설정은 Rancher에서 바꾼다.** `50-rancher.yaml`과 `registries.yaml`은 Rancher가 덮어쓴다. `dev` ⋮ → Edit Config에서 바꾼다.
- **업그레이드:** Edit Config에서 Kubernetes Version만 바꾸면 Rancher가 노드를 한 대씩 올린다. 새 버전의 이미지 묶음을 미리 넣어 두면 빠르다.
- **노드 제거:** Rancher 화면에서 먼저 지운다. 서버는 `rke2-uninstall.sh`, `rancher-system-agent-uninstall.sh`로 정리한다.
- **노드 추가:** worker만 늘릴 때는 등록 명령에서 Worker만 체크한다. 그 서버에는 `rke2-agent`가 설치된다.
- **Jenkins 배포:** Rancher에서 `dev` kubeconfig를 받아 Jenkins Credentials에 넣거나, Jenkins는 이미지·차트 push까지만 하고 Rancher Apps에서 배포한다.
