1.1 방화벽 비활성화 및 보안팀 신청
- RKE2 공식 문서 권장으로 firewalld 비활성화 필요
- firewalld가 Canal(CNI)이 만드는 iptables 규칙과 충돌하여 pod 통신이 끊어질 수 있음
```bash
sudo systemctl disable --now firewalld
     systemctl is-active firewalld #inactive
     systemctl is-enabled firewalld #disabled
```

- 사내 방화벽 허용 필요 요소

| Src             | Dst                                                                                                 | Port                 | 내용                                 |
| --------------- | --------------------------------------------------------------------------------------------------- | -------------------- | ---------------------------------- |
| 관리자 PC          | rancher cluster, rancher domain                                                                     | TCP 443              | Rancher UI·API                     |
| 관리자 PC          | rancher cluster, 환경별 클러스터                                                                           | TCP 22               | 설치·점검                              |
| 관리자 PC          | rancher cluster                                                                                     | TCP 6443             | 관리 클러스터 kubectl                    |
| 관리자 PC          | 환경별 클러스터, 환경별 클러스터 도메인                                                                              | TCP 80, 443          | 배포한 서비스 접속                         |
| 환경별 <br>클러스터    | rancher cluster, rancher domain                                                                     | TCP 443              | 에이전트 → Rancher 단방향 (필수)            |
| Jenkins 운영·개발   | rancher cluster, rancher domain                                                                     | TCP 443              | 배포                                 |
| 환경별 <br>클러스터    | Nexus                                                                                               | TCP 8081, 5000, 5001 | 이미지·차트 pull                        |
| rancher cluster | docker.io, registry-1.docker.io, auth.docker.io, production.cloudflare.docker.com, ghcr.io, quay.io | TCP 443              | 컨테이너 이미지 (설치 후에도 지속)               |
| rancher cluster | get.rke2.io, github.com, objects.githubusercontent.com, releases.rancher.com, charts.jetstack.io    | TCP 443              | RKE2 바이너리, Rancher·cert-manager 차트 |
| rancher cluster, 환경별 클러스터 | rpm.rancher.io | TCP 443 | RKE2·rke2-selinux RPM. Rocky에서 install.sh 기본 방식 (2차 신청) |
| rancher cluster | get.helm.sh | TCP 443 | Helm 바이너리 (2차 신청) |
| rancher cluster | release-assets.githubusercontent.com | TCP 443 | GitHub 릴리스 다운로드. github.com이 이 주소로 넘김 (2차 신청) |
| rancher cluster, 환경별 클러스터 | production.cloudfront.docker.com | TCP 443 | Docker Hub 이미지 데이터 CDN (AWS CloudFront). FQDN 허용 + TLS 검사 예외 (2차 신청) |

- 2차 신청 배경 (2026-10-19~20 실제 설치): 위 4행이 1차 목록에서 빠져 있었다. 신청서 양식에는 rancher cluster, 환경별 클러스터를 출발지별로 나눠 6건으로 적었다.
- rancher cluster → Nexus 5000은 신청하지 않는다. MGMT 3대 모두 이미 열려 있다(`401` 응답). docker.io에서 직접 받을 수 있어 Nexus mirror도 필수가 아니다. 신청 전 `curl -sI --max-time 5 https://<주소> -o /dev/null -w '%{http_code}\n' || echo 차단`으로 확인했다. 응답 코드가 나오면 열림이다.
- `production.cloudfront.docker.com`: Docker Hub가 이미지 데이터를 주는 또 하나의 CDN이다. 1차 목록에는 cloudflare만 있었다. 처음에는 작은 이미지 pull이 성공해 신청에서 뺐다. 이후 MGMT-2·3의 `rancher/rancher`(973MB) pull이 이 주소의 여러 IP(13.225.134.x)에서 `connection reset`, `timeout awaiting response headers`로 반복 실패했다. 같은 시점에 `rancher/shell`(114MB)은 성공했다. **작은 이미지 성공만으로 열렸다고 판단하지 않는다.** 큰 이미지로 확인한다.
- 이번 설치는 노드 간 이미지 복사(2. 설치 부록A.4)와 자동 재시도로 넘겼다. 방화벽이 열리기 전까지 새 노드·업그레이드마다 같은 문제가 난다.
- CDN 주소는 IP가 수시로 바뀐다. 도메인(FQDN) 기반 허용과 TLS 검사 예외를 함께 요청한다.
- `mirrors.fedoraproject.org`(EPEL)는 신청하지 않는다. RKE2·Rancher에 쓰지 않는다. 서버에서 `dnf config-manager --set-disabled epel`로 끈다.
- Nexus 5001은 신청 전에 Nexus 서버에서 `ss -lntp | grep 5001`로 실제로 열려 있는지 본다. 비어 있으면 방화벽이 아니라 Nexus HTTPS 설정 문제다.

1.2 NetworkManager 설정
- 서버 OS에서 NetworkManager는 신규 인터페이스를 자동으로 관리대상으로 포함시킴
- Canal(CNI)이 만드는 flannel.1, cali* 인터페이스를 건드리면 pod 네트워크가 문제가 되어 해당 인터페이스는 포함하지 않도록 하는 설정이 필요
  
- NetworkManager 상태 확인
  ```bash
  systemctl is-active NetworkManager
  
  #활성화
  active
  
  ```
  
- CNI 인터페이스 관리 제외

```bash
sudo mkdir -p /etc/NetworkManager/conf.d

sudo tee /etc/NetworkManager/conf.d/rke2-canal.conf > /dev/null <<'EOF'
[keyfile]
unmanaged-devices=interface-name:flannel*;interface-name:cali*;interface-name:tunl*;interface-name:vxlan.calico;interface-name:vxlan-v6.calico;interface-name:wireguard.cali;interface-name:wg-v6.cali
EOF

```

- 설정 적용
  ```bash
  sudo systemctl reload NetworkManager
  ```

 
 - nm-cloud-setup 설정 비활성화
 - nm-cloud-setup은 NetworkManager가 클라우드 환경의 네트워크 설정을 자동으로 구성하도록 도와주는 서비스임. nm-cloud-setup 도 Canal(CNI) 라우팅에 간섭할 수 있어서 AWS 등의 클라우드 네트워크를 사용하지 않는다면 비활성화 하는것을 권장함

```bash
# 패키지 설치 여부. "is not installed"면 아래 비활성화는 건너뜀
rpm -q NetworkManager-cloud-setup

# 서비스 활성화 여부
systemctl is-enabled nm-cloud-setup.service
systemctl is-enabled nm-cloud-setup.timer

# 서비스 설정 확인
systemctl cat nm-cloud-setup.service

# 현재 라우팅 정책 확인
ip rule show
ip route show table all

# 비활성화 (패키지가 설치된 경우만)
sudo systemctl disable --now nm-cloud-setup.service nm-cloud-setup.timer

# 확인: 두 줄 모두 disabled
systemctl is-enabled nm-cloud-setup.service nm-cloud-setup.timer

# nm-cloud-setup이 추가한 라우팅 규칙을 지우기 위해 재부팅
sudo reboot
```

- rancher cluster 관리자 화면에 들어갈때도 그렇고 클러스터에서 rancher에 접근할때도 도메인으로 접근하는걸 권장하기 때문에 도메인을 받는게 좋음

1.4 swap 비활성화
- kubelet은 swap이 켜져 있으면 기동을 거부함.
- 옵션으로 실행을 할 수는 있으나 etcd가 swap으로 밀리면 지연이 튀어 클러스터가 불안정해지므로 권장하지 않음
```bash
sudo swapoff -a

sudo sed -i.bak '/\sswap\s/s/^\([^#]\)/#\1/' /etc/fstab 
# swap 줄을 주석 처리, 원본은 fstab.bak


#확인
free -h | grep -i swap # Swap: 0B 0B 0B
grep -i swap /etc/fstab # 줄이 # 으로 시작
sudo swapon --show # 출력 없음

#재부팅 뒤에도 free -h 가 0이어야 함.
#systemd swap 유닛(*.swap)이 있으면 systemctl --type swap으로 확인해 mask 합니다.
```

- 권장하진 않지만 swap을 켜둔채 사용 하는 방법
```bash
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/90-swap.conf

sudo sysctl --system

sudo mkdir -p /var/lib/rancher/rke2/agent/etc/kubelet.conf.d

sudo tee /var/lib/rancher/rke2/agent/etc/kubelet.conf.d/90-swap.conf <<'EOT'
apiVersion: kubelet.config.k8s.io/v1beta1 
kind: KubeletConfiguration 
memorySwap: 
  swapBehavior: LimitedSwap 
EOT

# 이후에 Rancher UI에서 dev 클러스터를 만들 때 
#Advanced → Additional Kubelet Args에 fail-swap-on=false를 넣습니다.

```


1.5 docker 비활성화
- RKE2는 자체 containerd 사용. Docker가 떠 있으면 iptables FORWARD 정책을 DROP으로 바꾸고 자기 containerd와 포트를 점유해 Pod 통신이 간헐적으로 끊어짐. 삭제는 안 해도 되고 서비스만 내림.
```bash
# 먼저 확인. 운영 중인 컨테이너가 있으면 그 서비스를 옮긴 뒤에 끈다
systemctl is-active docker # active 면 설치됨

sudo docker ps # 컨테이너 목록. 비어 있어야 함

# 서비스 중지와 자동 시작 해제
sudo systemctl disable --now docker docker.socket containerd

# 확인
systemctl is-active docker docker.socket containerd # 세 줄 모두 inactive
systemctl is-enabled docker # disabled
ss -lntup | grep -E ':(80|443|2379|2380|6443|9345|9099|10250)\s' # 출력 없음 (포트 비어 있음)

# Docker가 남긴 흔적. 아래 셋 중 하나라도 기준과 다르면 재부팅 후 RKE2 설치
ip -br link | grep docker0 # 출력 없어야 함
sudo iptables -S FORWARD | head -1 # -P FORWARD ACCEPT 여야 함
sudo iptables -S | grep -c DOCKER # 0 이어야 함
sudo reboot # 흔적이 있을 때만
```

- Docker를 꺼도 `docker0` 브리지, DOCKER 체인, `FORWARD DROP` 정책은 남는다. 서비스만 내리면 정리되지 않는다.
- `FORWARD DROP`이 남으면 노드 사이 Pod 통신이 막힌다. 실제 설치에서 MGMT-1이 Docker를 켠 채 설치됐고, 끄고 재부팅한 뒤에 조인을 진행했다.
- 이미 RKE2가 돌고 있는 클러스터 노드는 한 대씩 재부팅한다. etcd가 2개일 때는 재부팅하지 않는다.

1.6 폴더 마운트(선택)
	
- 데이터 및 로그가 특정 디렉토리를 사용해야할 때 적용
- RKE2의 data-dir 옵션으로 경로를 바꾸면 Rancher 기본 경로가 달라져 운영이 번거로움
- 기본 경로는 그대로 사용하고 디스크만 특정 디렉토리를 쓰도록 바인드 마운트 함

- 기본경로

| 경로                 | 내용                                      |
| ------------------ | --------------------------------------- |
| `/var/lib/rancher` | RKE2 바이너리, 이미지, etcd, 매니페스트. 가장 큰 용량 차지 |
| `/var/lib/kubelet` | Pod 임시 볼륨(emptyDir)                     |
| `/var/log/pods`    | 컨테이너 로그                                 |

- 예시) 특정 디렉토리가 /app일때
- `/app`이 먼저 마운트돼 있어야 함. `x-systemd.requires-mounts-for=/app`은 부팅 때 `/app` 마운트가 끝난 뒤 bind mount 하라는 옵션
- `/var/lib/rancher` 등에 이미 데이터가 있으면 마운트하는 순간 기존 내용이 가려짐. RKE2 설치 전에 수행
```bash
# 0) /app 마운트 확인, 중복 등록 방지
mountpoint -q /app || { echo '/app이 마운트되지 않음'; exit 1; }
grep -q '/app/rke2/rancher' /etc/fstab && { echo 'fstab에 이미 등록됨'; exit 1; }

# 1) 실제 저장 디렉터리
sudo mkdir -p /app/rke2/rancher /app/rke2/kubelet /app/rke2/log-pods

# 2) 마운트 지점
sudo mkdir -p /var/lib/rancher /var/lib/kubelet /var/log/pods

# 3) fstab 등록 (공백 수는 자유, EOT 는 줄 맨 앞)
sudo tee -a /etc/fstab >/dev/null <<'EOT'
/app/rke2/rancher  /var/lib/rancher  none  defaults,bind,x-systemd.requires-mounts-for=/app  0 0
/app/rke2/kubelet  /var/lib/kubelet  none  defaults,bind,x-systemd.requires-mounts-for=/app  0 0
/app/rke2/log-pods /var/log/pods     none  defaults,bind,x-systemd.requires-mounts-for=/app  0 0
EOT

# 4) 적용
sudo systemctl daemon-reload
sudo mount -a

#확인
findmnt | grep rke2
# /var/lib/rancher /dev/mapper/vg_app-lv_app[/rke2/rancher] xfs ...
# /var/lib/kubelet /dev/mapper/vg_app-lv_app[/rke2/kubelet] xfs ...
# /var/log/pods /dev/mapper/vg_app-lv_app[/rke2/log-pods] xfs ...

df -h /var/lib/rancher # /app 과 같은 장치, 같은 용량
```
