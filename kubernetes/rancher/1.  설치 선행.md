1.2 NetworkManager 설정
- 서버 OS에서 NetworkManager는 신규 인터페이스를 자동으로 관리대상으로 포함시킴
- Canal(CNI)이 만드는 flannel.1, cali* 인터페이스를 건드리면 pod 네트워크가 문제가 되어 해당 인터페이스는 포함하지 않도록 하는 설정이 필요
  
- NetworkManager 상태 확인
  ```bash
  systemctl is-active NetworkManager
  
  #활성화
  active
  
  ```
  
- CNI 인터페이스 관리 제외

```bash
sudo mkdir -p /etc/NetworkManager/conf.d

sudo tee /etc/NetworkManager/conf.d/rke2-canal.conf > /dev/null <<'EOF'
[keyfile]
unmanaged-devices=interface-name:flannel*;interface-name:cali*;interface-name:tunl*;interface-name:vxlan.calico;interface-name:vxlan-v6.calico;interface-name:wireguard.cali;interface-name:wg-v6.cali
EOF

```

- 설정 적용
  ```bash
  sudo systemctl reload NetworkManager
  ```

 
 - nm-cloud-setup 설정 비활성화
 - nm-cloud-setup은 NetworkManager가 클라우드 환경의 네트워크 설정을 자동으로 구성하도록 도와주는 서비스임. nm-cloud-setup 도 Canal(CNI) 라우팅에 간섭할 수 있어서 AWS 등의 클라우드 네트워크를 사용하지 않는다면 비활성화 하는것을 권장함
   ```bash
# 패키지 설치 여부
rpm -q NetworkManager-cloud-setup

# 서비스 활성화 여부
systemctl is-enabled nm-cloud-setup.service
systemctl is-enabled nm-cloud-setup.timer

# 서비스 설정 확인
systemctl cat nm-cloud-setup.service

# 현재 라우팅 정책 확인
ip rule show
ip route show table all
   ```

1.4 swap 비활성화
- kubelet은 swap이 켜져 있으면 기동을 거부함.
- 옵션으로 실행을 할 수는 있으나 etcd가 swap으로 밀리면 지연이 튀어 클러스터가 불안정해지므로 권장하지 않음
```bash
sudo swapoff -a

sudo sed -i.bak '/\sswap\s/s/^\([^#]\)/#\1/' /etc/fstab 
# swap 줄을 주석 처리, 원본은 fstab.bak


#확인
free -h | grep -i swap # Swap: 0B 0B 0B
grep -i swap /etc/fstab# 줄이 # 으로 시작
sudo swapon --show # 출력 없음

#재부팅 뒤에도 free -h 가 0이어야 함.
#systemd swap 유닛(*.swap)이 있으면 systemctl --type swap으로 확인해 mask 합니다.
```

- 권장하진 않지만 swap을 켜둔채 사용 하는 방법
```bash
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/90-swap.conf

sudo sysctl --system

sudo mkdir -p /var/lib/rancher/rke2/agent/etc/kubelet.conf.d

sudo tee /var/lib/rancher/rke2/agent/etc/kubelet.conf.d/90-swap.conf <<'EOT'
apiVersion: kubelet.config.k8s.io/v1beta1 
kind: KubeletConfiguration 
memorySwap: 
  swapBehavior: LimitedSwap 
EOT

# 이후에 Rancher UI에서 dev 클러스터를 만들 때 
#Advanced → Additional Kubelet Args에 fail-swap-on=false를 넣습니다.

```


1.5 docker 비활성화
- RKE2는 자체 containerd 사용. Docker가 떠 있으면 iptables FORWARD 정책을 DROP으로 바꾸고 자기 containerd와 포트를 점유해 Pod 통신이 간헐적으로 끊어짐. 삭제는 안 해도 되고 서비스만 내림.
```bash
먼저 확인.운영 중인 컨테이너가 있으면 그 서비스를 옮긴 뒤에 끕니다. 
systemctl is-active docker # active 면 설치됨

sudo docker ps# 컨테이너 목록. 비어 있어야 함

서버 (sudo)

sudo systemctl disable --now docker docker.socket containerd

확인

systemctl is-active docker docker.socket containerd # 세 줄 모두 inactive
systemctl is-enabled docker # disabled
ss -lntup | grep -E ':(80|443|2379|2380|6443|9345|9099|10250)\s' # 출력 없음 (포트 비어 있음)

ip -br link | grep docker0 # 남아 있어도 무해. 재부팅하면 사라짐
```

1.6 폴더 마운트(선택)
	
- 데이터 및 로그가 특정 디렉토리를 사용해야할 때 적용
- RKE2의 data-dir 옵션으로 경로를 바꾸면 Rancher 기본 경로가 달라져 운영이 번거로움
- 기본 경로는 그대로 하용하고 디스크만 특정 디렉토리를 쓰도록 바인드 마운트 함

- 기본경로

| 경로                 | 내용                                      |
| ------------------ | --------------------------------------- |
| `/var/lib/rancher` | RKE2 바이너리, 이미지, etcd, 매니페스트. 가장 큰 용량 차지 |
| `/var/lib/kubelet` | Pod 임시 볼륨(emptyDir)                     |
| `/var/log/pods`    | 컨테이너 로그                                 |

- 예시) 특정 디렉토리가 /app일때
```bash
# 1) 실제 저장 디렉터리

sudo mkdir -p /app/rke2/rancher /app/rke2/kubelet /app/rke2/log-pods

# 2) 마운트 지점
sudo mkdir -p /var/lib/rancher /var/lib/kubelet /var/log/pods

# 3) fstab 등록 (공백 수는 자유, EOT 는 줄 맨 앞)

sudo tee -a /etc/fstab <<'EOT'
/app/rke2/rancher /var/lib/rancher none  bind  0 0 
/app/rke2/kubelet /var/lib/kubelet none  bind  0 0
/app/rke2/log-pods /var/log/pods none  bind  0 0 
EOT

# 4) 적용

sudo systemctl daemon-reload
sudo mount -a
sudo mkdir -p /var/lib/rancher /var/lib/kubelet /var/log/pods

# 3) fstab 등록 (공백 수는 자유, EOT 는 줄 맨 앞)

sudo tee-a /etc/fstab <<'EOT'
/app/rke2/rancher /var/lib/rancher none  bind  0 0 
/app/rke2/kubelet /var/lib/kubelet none  bind  0 0 
/app/rke2/log-pods /var/log/pods none  bind  0 0 
EOT

# 4) 적용

sudo systemctl daemon-reload
sudo mount -a

#확인

findmnt | grep rke2
# /var/lib/rancher /dev/mapper/vg_app-lv_app[/rke2/rancher] xfs ...
# /var/lib/kubelet /dev/mapper/vg_app-lv_app[/rke2/kubelet] xfs ...
# /var/log/pods /dev/mapper/vg_app-lv_app[/rke2/log-pods] xfs ...

df -h /var/lib/rancher # /app 과 같은 장치, 같은 용량
```
