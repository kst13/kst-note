# 앱 배포 — Jenkins → Nexus → Rancher Apps

[3. DEV 클러스터 설치](3.%20DEV%20클러스터%20설치.md) 10장(VIP, Traefik, 인증서)까지 끝낸 뒤 진행한다. 기존에 Docker로 운영하던 웹(Vue SPA + nginx)과 WAS(Spring Boot)를 클러스터로 옮기는 표준이다. 저장소가 달라도 모두 같은 구조를 따른다.

역할은 이렇게 나눈다.

- **Jenkins:** 이미지와 차트를 같은 버전으로 만들어 Nexus에 올린다. 배포는 하지 않는다.
- **Rancher Apps:** 담당자가 버전을 골라 설치·업그레이드·롤백한다.

## 0. Docker 운영과 무엇이 다른가

### 기존 구조

```text
사용자 ─https─▶ Docker 서버 한 대
                ├ proxy 컨테이너 (443)  인증서, 80→443, 경로 나누기
                │    └─▶ :81
                └ web 컨테이너 (80)     화면 파일 + API 넘기기
                WAS 컨테이너            docker run --add-host 로 DB 이름 붙임
```

### 지금 구조

```text
사용자 ─https─▶ <앱>.<도메인> = <DEV VIP>   (MetalLB, DEV 노드 한 대가 맡음)
                ▼
              Traefik (DEV 3대)              인증서, 도메인 보고 나누기
                ▼
              웹 Pod                         nginx 하나: 화면 파일 + 기존 proxy·web 경로 규칙 전부
                ├─▶ WAS Service (클러스터 안)  <서비스>.<네임스페이스>.svc.cluster.local
                └─▶ 레거시·외부 서버 (클러스터 밖)  IP 직접
```

| 기존 | 지금 | 이유 |
|---|---|---|
| proxy 컨테이너 | Traefik(TLS, 도메인) + 앱 nginx(경로 규칙) | Traefik은 클러스터에 하나. 앱마다 proxy를 둘 필요가 없음 |
| `ssl/*.pem`을 이미지에 복사 | `kube-system`의 TLS Secret | 이미지를 받은 사람이 개인키를 꺼낼 수 없음. 갱신도 한 곳 |
| proxy → `서버:81` → web | 같은 nginx 안에서 처리 | 한 단계가 줄어듦 |
| 미리 빌드한 `dist`·jar를 이미지에 복사 | Dockerfile 안에서 빌드 | 누가 어디서 빌드해도 결과가 같음 |
| `docker run -e`, `--add-host` | Helm 차트 values → env, `hostAliases` | 설정이 git에 남고 환경별로 나뉨 |
| `docker run` | Rancher Apps에서 Helm 차트 설치 | 버전 선택, 끊김 없는 교체, 롤백 |

### 앱이 여러 개일 때

| 하던 일 | 맡는 곳 |
|---|---|
| TLS 인증서, 80→443 | Traefik (클러스터에 하나) |
| 도메인별로 앱 나누기 | 앱마다 Ingress 하나 (차트에 포함) |
| 경로, Referer, 경로 바꾸기, 레거시 서버, 스트리밍 설정 | 각 앱의 nginx |

공용 proxy 하나에 모든 앱 규칙을 모으지 않는다. 한 앱의 경로를 바꾸려고 공용 proxy를 다시 배포해야 하고, 설정 실수 하나가 모든 사이트를 멈추게 한다.

## 1. 저장소 표준: `deploy/k8s/`

**기존 stage·운영 배포에 영향을 주지 않는 것이 원칙이다.** 루트의 Dockerfile, nginx.conf, 소스는 고치지 않는다. 쿠버네티스용 파일은 모두 `deploy/k8s/` 아래에 새로 만든다.

```text
<저장소>/
└── deploy/k8s/
    ├── Dockerfile               # 빌드 컨텍스트는 저장소 루트
    ├── Dockerfile.dockerignore  # 이 Dockerfile 빌드에만 적용
    ├── Jenkinsfile              # Jenkins Job 의 Script Path
    ├── env.local.example        # (웹) 로컬 docker run 용 환경변수 예시
    ├── nginx/                   # (웹)
    │   ├── default.conf.template
    │   ├── proxy-common.conf
    │   └── 05-resolver.envsh
    └── chart/
        ├── Chart.yaml
        ├── values.yaml
        └── templates/  _helpers.tpl, deployment.yaml, service.yaml, (웹) ingress.yaml
```

- **빌드 명령:** `docker build -f deploy/k8s/Dockerfile .` 처럼 저장소 루트에서 실행한다.
- **`Dockerfile.dockerignore`:** BuildKit은 Dockerfile 옆의 `<이름>.dockerignore`를 먼저 찾는다. 루트 `.dockerignore`를 건드리지 않아 기존 빌드가 그대로다.
- **브랜치:** 작업은 기존 브랜치에서 새 브랜치(예: `k8s-develop`)를 만들어 한다. 보호 브랜치(`develop`)에는 직접 push가 막혀 있으므로 MR로 합친다.
- **넣지 않는 것:** 인증서·키, 로컬 `env.local`, 기존 서버용 nginx 설정, Nexus 토큰이 든 파일의 변경.

## 2. 환경 분리 (dev / stage / prod)

Jenkins Job은 환경마다 하나씩 만들고 브랜치만 다르게 준다. Jenkinsfile 하나가 **빌드한 브랜치로 환경을 정한다.**

```groovy
// 브랜치 → 대상 환경. 여기에 없는 브랜치는 빌드를 멈춘다.
def TARGETS = [
  'develop'   : [env: 'dev',   helm: 'helm-hosted', mode: 'development'],
  'stage'     : [env: 'stage', helm: 'helm-stage',  mode: 'staging'],
  'production': [env: 'prod',  helm: 'helm-prod',   mode: 'production'],
]
```

| 환경 | 이미지 경로 | 차트 저장소(Nexus) | 화면 빌드 모드 |
|---|---|---|---|
| dev | `<NEXUS_HOST>:5000/dev/<그룹>/<앱>:1.0.N` | `helm-hosted` | development (`.env`) |
| stage | `.../stage/<그룹>/<앱>:1.0.N` | `helm-stage` | staging (`.env.staging`) |
| prod | `.../prod/<그룹>/<앱>:1.0.N` | `helm-prod` | production (`.env.production`) |

- **왜 나누나:** 빌드 번호는 Job마다 따로 센다. dev 1.0.5와 stage 1.0.5가 서로 다른 이미지가 된다. 경로와 저장소를 나누지 않으면 덮어쓰거나 잘못 받는다.
- **왜 웹은 환경마다 빌드하나:** Vite의 `VITE_*` 값은 빌드할 때 JS에 박힌다. 같은 이미지를 환경만 바꿔 쓸 수 없다.
- **`GIT_BRANCH`:** Pipeline script from SCM은 `origin/develop` 형태로 넣는다. 앞부분을 떼고 비교한다.
- **Rancher 저장소:** 클러스터마다 자기 환경 저장소만 등록한다. DEV Rancher에는 `helm-hosted`만 보인다.

### 환경 잠금: `environment`와 `builtFor`

Jenkins가 차트를 패키징하기 직전에 values의 두 값을 빌드한 환경으로 채운다.

```bash
sed -i -e "s|^environment: .*|environment: $DEPLOY_ENV|" \
       -e "s|^builtFor: .*|builtFor: $DEPLOY_ENV|" deploy/k8s/chart/values.yaml
grep -qx "builtFor: $DEPLOY_ENV" deploy/k8s/chart/values.yaml   # 못 바꿨으면 빌드 실패
```

- **`builtFor`:** 이미지 경로의 환경 부분이 된다 (`<registry>/<builtFor>/<image.name>`).
- **설치 차단:** Rancher 화면에서 `environment`를 다른 값으로 바꾸면 `_helpers.tpl`의 `fail`이 설치를 멈춘다. dev 이미지에 stage 주소가 들어가는 사고를 막는다.
- **빌드가 끝나면** `post`에서 `git checkout -- values.yaml`로 되돌린다.

## 3. 웹: Dockerfile

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json package-lock.json .npmrc ./
RUN npm ci --no-audit --no-fund
COPY . .
ARG BUILD_MODE=development
RUN npx vite build --mode ${BUILD_MODE}

FROM nginx:1.28
RUN ln -sf /usr/share/zoneinfo/Asia/Seoul /etc/localtime
# 환경과 관계없는 기본값만 둔다. 백엔드 주소는 차트 values 가 넣는다.
ENV LEGACY_HOST_HEADER=\$host \
    TRUSTED_PROXY_CIDR=10.42.0.0/16
RUN rm -f /etc/nginx/conf.d/default.conf
COPY deploy/k8s/nginx/default.conf.template /etc/nginx/templates/default.conf.template
COPY deploy/k8s/nginx/proxy-common.conf /etc/nginx/snippets/proxy-common.conf
COPY --chmod=755 deploy/k8s/nginx/05-resolver.envsh /docker-entrypoint.d/05-resolver.envsh
COPY --from=build /app/dist /usr/share/nginx/html
```

- **두 단계 빌드:** 최종 이미지에는 nginx와 화면 파일만 남는다.
- **백엔드 주소를 `ENV`에 두지 않는다.** 주소가 빠지면 템플릿에 `${...}`가 남아 nginx가 기동에 실패한다. 엉뚱한 주소로 조용히 뜨는 것보다 낫다.
- **`\$host`:** Dockerfile `ENV`의 `$`는 escape한다. 템플릿에 nginx 변수 `$host`로 들어간다.
- **`.npmrc`:** 사내 패키지(`@dns/*`)를 Nexus npm 저장소에서 받는다. Jenkins 서버에서 Nexus 8081과 `registry.npmjs.org`에 닿아야 한다.

### 빌드 전에 확인할 것

| 확인 | 안 맞으면 | 대응 |
|---|---|---|
| lock 파일이 `package.json`과 맞는가 | `npm ci`가 `lock file's ... does not satisfy` 로 실패 | lock을 다시 만들어 커밋. 당장은 `npm install`로 우회 |
| pnpm 저장소인가 | `pnpm-lock.yaml`만 최신 | `npm install -g pnpm@10` 후 `pnpm install --frozen-lockfile` |
| `tailwind.config.js`가 `module.exports`인데 `package.json`이 `"type": "module"` | Node 22에서 `module is not defined` | `node:20-alpine`으로 고정하거나 설정 파일을 `.cjs`로 |
| lock에 `@rollup/rollup-linux-x64-musl`, `@esbuild/linux-x64`가 있는가 | alpine에서 빌드 실패 | lock 재생성 |
| 모노레포인가 (npm workspaces) | 루트에서 빌드해야 함 | `npm run build -w=<앱> -- --mode ${BUILD_MODE}`, 결과는 `apps/<앱>/dist` |

## 4. 웹: nginx 템플릿 (proxy와 web을 하나로)

`/etc/nginx/templates/*.template`은 nginx 공식 이미지의 기능이다. 시작할 때 `${변수}`를 환경변수 값으로 바꿔 `conf.d/`에 설정 파일을 만든다. 백엔드 주소가 환경마다 달라도 이미지를 다시 만들지 않는다.

### 값이 들어가는 순서

```text
values.yaml profiles.<env>.backends.xxxApi
  → (Rancher 설치) Deployment env  XXX_API=http://...
  → (Pod 시작) envsubst: set $xxx_api http://...;
  → (요청마다) proxy_pass $xxx_api;   resolver 로 이름을 찾음
```

빌드할 때가 아니라 **Pod가 시작할 때** 값이 들어간다. 주소만 바꿀 때도 차트를 새로 빌드해 Upgrade한다 (8장).

### 합칠 때 지킨 원칙

**규칙 순서를 기존과 같게 맞춘다.** 기존에는 proxy 규칙을 먼저 거치고 남은 요청만 web으로 갔다. nginx location 우선순위는 다음과 같다.

1. `=` 정확히 일치
2. 가장 긴 접두사 중 `^~`
3. 정규식(`~`, `~*`), 파일에 적힌 순서
4. 가장 긴 일반 접두사

기존 proxy의 정규식(`\.do$`, 레거시 정적 파일)은 web 쪽 경로보다 먼저 걸렸다. 그래서 web 쪽 경로는 `^~` 없이 일반 접두사로 둔다. proxy가 Referer와 상관없이 늘 web으로 보내던 화면 경로는 `^~`로 정규식보다 앞에 둔다.

| 요청 | 기존 | 합친 설정 |
|---|---|---|
| `~ \.do$` | proxy → 레거시 서버 | 같음 |
| `~* ^/(css\|js\|calendar\|static\|images)` | proxy → 레거시 서버 | 같음 |
| `/api/oim/` | proxy → 회원 서버 (`/api/`로 바꿔서) | 같음 |
| `^~ /toss-api/` | proxy → 결제사 API | 같음 |
| `^~ /<화면 경로>` | proxy → web (Referer 무시) | 바로 `index.html` |
| `/api/<업무>` | proxy → web → 백엔드 | 바로 백엔드 (Referer 규칙 유지) |
| 그 밖 | proxy → web → `index.html` | 바로 `index.html` (Referer 규칙 유지) |

**Referer 규칙:** 레거시 `.do` 페이지에서 온 요청은 레거시 서버로 보낸다. `if` 안에서 `proxy_pass`를 쓰면 문제가 생기기 쉽다. 그래서 `if`에서는 418을 신호로 보내고 이름 붙은 location이 받는다.

```nginx
map $http_referer $from_legacy { default 0; "~*\.do" 1; }

error_page 418 = @legacy;

location / {
    if ($from_legacy) { return 418; }
    try_files $uri $uri/ /index.html;
}

location @legacy {
    include /etc/nginx/snippets/proxy-common.conf;
    proxy_set_header Host ${LEGACY_HOST_HEADER};
    proxy_pass $legacy;
}
```

### 쿠버네티스에 맞춰 바꾼 것

| 항목 | 기존 | 바꾼 것 | 이유 |
|---|---|---|---|
| 백엔드 주소 | `upstream { server host:port; }` | `set $api ${API};` 후 `proxy_pass $api;` | `upstream`은 시작할 때 DNS를 찾는다. 하나만 실패해도 nginx가 뜨지 않는다. 변수는 요청할 때 찾는다 |
| DNS | `resolver 8.8.8.8` | `resolver ${DNS_SERVER}` (`05-resolver.envsh`가 `/etc/resolv.conf`에서 읽음) | 클러스터 DNS(CoreDNS)로 찾아야 Service 이름이 풀린다 |
| 가짜 호스트 이름 | `docker run --add-host txm.x.com:IP` | values에 IP를 직접 | 변수 `proxy_pass`는 `/etc/hosts`를 보지 않는다 |
| 클러스터 안 백엔드 | 서버 IP | `<서비스>.<네임스페이스>.svc.cluster.local:<포트>` | 변수 `proxy_pass`는 search 도메인을 붙이지 않는다. 짧은 이름으로는 못 찾는다 |
| TLS | proxy가 `listen 443 ssl` | `listen 80`만 | Traefik이 TLS를 푼다 |
| 사용자 IP | proxy가 직접 봄 | `set_real_ip_from ${TRUSTED_PROXY_CIDR}; real_ip_header X-Forwarded-For;` | Traefik을 거치면 `$remote_addr`가 Traefik Pod IP가 된다 |
| `X-Forwarded-Proto` | `$scheme` (https) | Traefik이 준 값을 넘김 (`map $http_x_forwarded_proto`) | nginx에는 http로 들어온다 |
| 리다이렉트 | 절대 URL | `absolute_redirect off` | `http://…`로 내려가지 않게 한다 |
| 외부 HTTPS 백엔드 | `proxy_pass https://...` | `proxy_ssl_server_name on;` 추가 | SNI가 없으면 CDN·클라우드 API가 TLS를 거절한다 |
| 로그 | 파일 | 기본 `access.log`(stdout) | Rancher·`kubectl logs`로 본다 |

- location 안에 `proxy_set_header`가 하나라도 있으면 바깥 설정이 상속되지 않는다. 공통 헤더는 `proxy-common.conf`로 빼서 각 location에서 `include`한다.
- envsubst는 정의된 환경변수만 바꾼다. nginx 변수(`$host`, `$uri`)는 소문자라 건드리지 않는다.
- 백엔드 하나가 아직 없으면 그 경로만 502가 나고 Pod는 정상으로 뜬다.

### 시작 로그

```text
Sourcing /docker-entrypoint.d/05-resolver.envsh
10-listen-on-ipv6-by-default.sh: info: /etc/nginx/conf.d/default.conf is not a file or does not exist

```

IPv6 안내는 무시한다. 기본 `default.conf`를 지웠고 템플릿은 20번 스크립트에서 만들어진다.

## 5. WAS: Dockerfile과 차트

```dockerfile
FROM amazoncorretto:21 AS build          # Gradle 7.x 저장소는 JDK 11 (아래 표)
WORKDIR /src
RUN yum install -y findutils             # gradlew 가 xargs 를 씀
COPY gradlew settings.gradle build.gradle gradle.properties ./
COPY gradle gradle
RUN chmod +x gradlew                     # git 에 실행 권한이 없는 저장소가 있다
RUN ./gradlew --no-daemon dependencies > /dev/null
COPY src src
RUN ./gradlew --no-daemon clean bootJar -x test && cp build/libs/*.jar /app.jar

FROM amazoncorretto:21
ENV TZ=Asia/Seoul \
    JAVA_OPTS="-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError"
WORKDIR /app
COPY --from=build /app.jar /app/app.jar
RUN mkdir -p /app/logs && chown -R 1000:1000 /app
USER 1000
EXPOSE <포트>
ENTRYPOINT ["sh","-c","exec java $JAVA_OPTS -jar /app/app.jar"]
```

- **`MaxRAMPercentage=75`:** JVM 힙을 컨테이너 메모리 limit의 75%로 잡는다. limit을 넘기면 커널이 죽이므로(OOMKilled) 여유를 둔다.
- **`ExitOnOutOfMemoryError`:** 힙이 모자라면 바로 종료해 쿠버네티스가 다시 띄우게 한다. 반쯤 죽은 채로 남지 않는다.
- **`exec`:** java가 PID 1이 되어 종료 신호(SIGTERM)를 직접 받는다. 교체할 때 요청을 마무리하고 내려간다.
- **`USER 1000`:** root로 돌리지 않는다. 쓰는 폴더(`/app`)만 소유권을 준다.

### 빌드에서 만난 경우

| 경우 | 증상 | 대응 |
|---|---|---|
| Gradle 7.2 | JDK 17+에서 `Unsupported class file major version 65` | 빌드·실행 이미지를 `amazoncorretto:11` |
| 빌드 중 가짜 호스트(`ows-nexus`)로 사내 라이브러리를 받음 | `Could not resolve ...` | Jenkinsfile에서 `docker build --add-host "<이름>:<IP>"` |
| `gradlew` 실행 권한 없음 | `./gradlew: Permission denied` (exit 126) | Dockerfile에 `RUN chmod +x gradlew` |
| 네이티브 라이브러리(SAP JCo `.so`) | `UnsatisfiedLinkError` | 실행 이미지에 `.so` 복사 + `-Djava.library.path`, 의존 패키지(`libuuid`, `libstdc++`) 설치 |
| 앱이 작업 폴더에 파일을 씀 | `AccessDeniedException` | `/app` 소유권을 1000에 |

### 차트에서 바뀌는 것

| 기존 `docker run` | 차트 | 비고 |
|---|---|---|
| `--add-host ows-devdb:<DB_IP>` | `profiles.<env>.hostAliases` | Pod의 `/etc/hosts`에 들어간다. Java는 `/etc/hosts`를 본다 |
| `-e SPRING_PROFILES_ACTIVE=dev` | `profiles.<env>.springProfile` | |
| `application.yml`의 값 바꾸기 | `profiles.<env>.env` | Spring relaxed binding: `txm.url` → `TXM_URL`, `service.dns-job.host` → `SERVICE_DNSJOB_HOST` |
| `-p 9060:9060` | Service `<업무>-backend:<포트>` | 웹이 FQDN으로 부름. Ingress는 없음 |
| 로그 파일 | `/app/logs` emptyDir (sizeLimit 1Gi) | Pod가 바뀌면 사라짐. 오래 볼 로그는 [5. 운영](5.%20운영%20(로그%20자원%20문제%20해결).md) |

```yaml
profiles:
  dev:
    springProfile: dev
    replicas: 1
    hostAliases:
      - ip: "<DEV_DB_IP>"
        hostnames: ["ows-devdb"]
    env:
      TXM_URL: "http://<TXM_IP>:9901/txm"
      # Eureka 에 등록하면 게이트웨이가 클러스터 안 Pod 로 트래픽을 보낸다. 준비되기 전에는 끈다.
      EUREKA_CLIENT_REGISTERWITHEUREKA: "false"
      EUREKA_CLIENT_FETCHREGISTRY: "false"
```

- **프로브는 tcpSocket:** 앱에 헬스 엔드포인트가 없어도 포트가 열렸는지로 판단한다. Spring 기동이 길어 startupProbe로 최대 3분(5초 × 36)을 기다린다.
- **클러스터 밖으로 나가는 주소:** DB, Redis, 파일 서버, SAP는 방화벽 출발지가 DEV 노드 3대로 바뀐다. 처음 띄울 때 CrashLoopBackOff면 방화벽부터 본다.

## 6. Helm 차트 구조

```yaml
environment: dev          # Jenkins 가 채움. Rancher 에서 바꾸지 않음
builtFor: ""              # Jenkins 가 채움. 이미지 경로 앞부분
image:
  registry: <NEXUS_HOST>:5000
  name: <그룹>/<앱>
  tag: ""                 # 비우면 Chart.appVersion (= 1.0.N)
profiles:                 # 환경별 값. 바뀌면 여기를 고치고 Jenkins 로 새 버전을 냄
  dev:   { host: dev-<앱>.<도메인>, replicas: 1, backends: {...} }
  stage: { host: "", replicas: 2, backends: {...} }
  prod:  { host: "", replicas: 2, backends: {...} }
overrides:                # 급할 때 Rancher 화면에서 한두 개만 덮어씀. git 에 남지 않음
  host: ""
  replicas: null          # 0 도 유효. 비우면 profile 값
  backends: {}
```

- **`_helpers.tpl`의 `<차트>.profile`:** `profiles[environment]`에 `overrides`를 덮어 하나로 만든다. 템플릿은 이 결과만 쓴다.
- **필수값 검사:** 고른 환경의 백엔드가 비어 있으면 `required`가 어떤 키가 비었는지 알려 주고 설치를 멈춘다. Jenkins의 `helm lint`도 dev 기준으로 같은 검사를 한다.
- **stage·prod를 비워 두면** 그 환경 빌드는 lint에서 멈춘다. 그 환경으로 옮길 때 채운다.
- **버전 규칙:** 이미지 태그 = 차트 버전 = appVersion = `1.0.<빌드번호>`. `latest`는 쓰지 않는다.
- **라벨:** `app.kubernetes.io/environment`, `app.kubernetes.io/version`을 붙여 어떤 환경·버전이 떠 있는지 바로 보이게 한다. 이미지에는 `org.opencontainers.image.revision=<커밋>` 라벨을 붙인다.

### 언제 무엇이 적용되나

| 시점 | 일어나는 일 | values가 쓰이나 |
|---|---|---|
| Jenkins `docker build` | 소스 빌드, 이미지 생성. `chart/`는 dockerignore로 빠짐 | 아니오 |
| Jenkins `helm lint`·`package` | 차트를 `<차트>-1.0.N.tgz`로 묶어 Nexus에 올림 | 검사만 |
| Rancher 설치·Upgrade | values로 템플릿을 렌더링해 Deployment·Service·Ingress 생성 | 예 |
| Pod 시작 | env 주입, `/etc/hosts` 작성, (웹) envsubst | 결과가 적용됨 |

```bash
helm lint deploy/k8s/chart
helm template t deploy/k8s/chart | less
helm template t deploy/k8s/chart --set builtFor=dev --set environment=stage   # 설치가 멈추는지 확인
```

## 7. Jenkins

Job 설정: New Item → Pipeline → **Pipeline script from SCM** → Git URL, GitLab 계정 → Branch `*/<브랜치>` → Script Path `deploy/k8s/Jenkinsfile`.

```text
Resolve target    브랜치 → env, Helm 저장소, 빌드 모드. 빌드 설명에 "<브랜치> → dev 1.0.N"
Build & push      docker build -f deploy/k8s/Dockerfile → login → push → logout
Package & push    values 에 환경 새김 → helm lint → helm package → curl 업로드
post              values 되돌림, 로컬 이미지 삭제
```

| 단계 | 증상 | 원인 |
|---|---|---|
| Resolve target | `브랜치 '...' 에 정해진 환경이 없습니다` | `TARGETS`에 없는 브랜치. 맞는 줄을 추가 |
| `npm ci` | `ETIMEDOUT`, `ECONNRESET` | Jenkins → `registry.npmjs.org` 막힘. Nexus npm 프록시로 우회 |
| `npm ci` | `401`/`404` (`@dns/*`) | `.npmrc` 토큰 또는 Nexus 권한 |
| `docker push` | `unauthorized` | Credentials 계정에 `docker-hosted` 쓰기 권한 없음 |
| `helm lint` | `... is required` | 고른 환경의 profile 값이 비어 있음 |
| `curl --upload-file` | `400` | 같은 버전 차트가 이미 있음. helm-hosted는 덮어쓰기 금지 |
| `git push` | `pre-receive hook declined` | 보호 브랜치. 새 브랜치로 push 후 MR |

빌드 뒤 이미지를 직접 확인할 때는 다시 로그인한다. Jenkinsfile이 push 직후 `docker logout`해서 로그인 없이 받으면 `unauthorized`가 난다.

```bash
docker login <NEXUS_HOST>:5000
docker run --rm <NEXUS_HOST>:5000/dev/<그룹>/<앱>:1.0.<N> nginx -t     # 웹: syntax is ok
docker logout <NEXUS_HOST>:5000
```

## 8. Rancher에서 설치·업그레이드

### 8.1 차트 저장소 등록 (클러스터마다 한 번)

`dev` → **Apps** → **Repositories** → **Create**

| 항목 | 값 |
|---|---|
| Target | **Helm Repository** (HTTP(S) URL pointing to a Helm chart repository index) |
| Name | `nexus` |
| Index URL | `http://<NEXUS_HOST>:8081/repository/helm-hosted/` (stage 클러스터는 `helm-stage`) |
| Authentication | 익명 읽기가 켜져 있으면 None, 아니면 HTTP Basic + 읽기 계정 |

목록은 DEV가 아니라 MGMT의 Rancher Pod가 읽는다. 그래서 MGMT → Nexus 8081 방화벽이 필요하다.

### 8.2 처음 설치

**네임스페이스를 먼저 정한다.** Apps 화면 위쪽 네임스페이스 필터를 앱 네임스페이스로 바꾼 뒤 시작한다.

**Apps** → **Charts** → 저장소 필터 `nexus` → 앱 → **Install**

| 항목 | 값 |
|---|---|
| Namespace | 앱 이름 (예: `otw-was`). 없으면 새로 만들기 |
| Name | 앱 이름 |
| Version | 올린 버전 |
| Values | 그대로. `environment`는 바꾸지 않음 |

```bash
kubectl -n <ns> get pods,svc,ingress
kubectl -n <ns> logs deploy/<앱> --tail=50
```

**실수 사례: `default` 네임스페이스에 설치.** Helm 릴리스는 네임스페이스를 옮길 수 없다. Installed Apps에서 지우고 다시 설치한다. 같은 도메인 Ingress가 두 곳에 있으면 Traefik이 헷갈리므로 먼저 지운다.

### 8.3 새 버전 올리기

1. **Apps** → **Repositories** → `nexus` ⋮ → **Refresh**. 새 버전이 목록에 보이게 한다.
2. **Installed Apps** → 앱 ⋮ → **Edit/Upgrade**.
3. **Version**에서 새 버전을 고른다.
4. Values는 그대로 두고 **Upgrade**.

새 Pod가 준비되면 옛 Pod를 내린다. 새 Pod가 준비되지 않으면 옛 Pod가 계속 서비스한다. 되돌릴 때는 Installed Apps → **Rollback** → 리비전을 고른다.

### 8.4 Pod 수(replicas)는 차트로만 바꾼다

**Rancher 워크로드 화면의 +/− (Scale)를 쓰지 않는다.** 차트의 `overrides.replicas`를 Upgrade로 바꾼다.

Rancher 화면에서 Scale하면 `spec.replicas`의 주인이 Rancher(`agent`)로 기록된다. 다음 Helm Upgrade가 같은 필드를 쓰려다 충돌하고 실패한다.

```text
Upgrade "otw-was" failed: conflict with "agent" using apps/v1: .spec.replicas
```

**복구:** 그 Deployment를 지우고 다시 Upgrade한다. Helm이 새로 만들며 주인이 Helm으로 돌아온다. 그동안 그 앱은 잠시 내려간다.

```bash
kubectl -n <ns> delete deploy <앱>
# Installed Apps 에서 같은 버전으로 Edit/Upgrade (failed 상태여도 Upgrade 가능)
```

### 8.5 무엇을 바꾸면 무엇을 해야 하나

| 바꾸는 것 | 필요한 작업 |
|---|---|
| 소스, Dockerfile, nginx 템플릿 | 커밋 → Jenkins → Upgrade |
| 백엔드 주소, 도메인, hostAliases, env (profiles) | 커밋 → Jenkins → Upgrade |
| 급한 임시 변경 | Upgrade 화면에서 `overrides`만. 끝나면 profiles에 반영하거나 지움 |
| Pod 수 | `overrides.replicas`로 Upgrade |
| 앱을 잠시 멈춤 (재시작 반복 등) | `overrides.replicas: 0`으로 Upgrade |

## 9. 새 앱을 올릴 때 순서

1. 이미 끝낸 저장소(웹이면 otw-web, WAS면 otw-was)의 `deploy/k8s/`를 복사한다.
2. 이름을 바꾼다: 차트 이름, 템플릿 define 이름, `IMAGE_PATH`, `CHART`, Service 이름·포트, 네임스페이스.
3. Dockerfile을 저장소에 맞춘다: Node·JDK 버전, lock 파일 종류, 빌드 결과 폴더.
4. (웹) 기존 proxy·web nginx 설정을 4장 원칙으로 합친다.
5. (WAS) `--add-host`를 hostAliases로, 환경별 설정을 env로 옮긴다.
6. dev profile을 채우고 `helm lint`, `helm template`으로 확인한다.
7. `TARGETS`에 이 저장소의 dev 브랜치를 넣는다.
8. 새 브랜치에 커밋·push → Jenkins Job → Rancher 설치.
9. (웹) 도메인 DNS를 DEV VIP로, 방화벽을 DEV 노드 출발로 요청한다.

## 10. 지켜볼 것

- **레거시·백엔드가 받는 Host:** 요청 Host(dev 도메인)가 그대로 넘어간다. 백엔드가 모르는 이름이라 거절하면 values `legacyHostHeader`에 아는 이름을 넣는다.
- **방화벽 출발지:** 클러스터 밖으로 가는 요청의 출발지가 DEV 노드 3대다. 화면은 뜨는데 API가 502면 이것부터 본다.
- **Eureka·게이트웨이:** 게이트웨이를 거치는 API는 Eureka에 등록된 서버로 간다. 클러스터 안 WAS가 등록하지 않으면 웹 nginx에서 그 WAS로 바로 보낸다.
- **`.do`로 끝나는 SPA 경로:** `~ \.do$` 규칙에 걸려 레거시 서버로 간다. 기존 동작 그대로다.
- **설정 파일 속 비밀값:** `application.yml`의 DB 비밀번호, 토큰은 나중에 Secret으로 옮긴다. 차트 values에는 넣지 않는다.
- **Traefik 설정:** 80→443 리다이렉트와 큰 업로드의 시간 제한. [3. DEV 클러스터 설치](3.%20DEV%20클러스터%20설치.md) 10.5.
