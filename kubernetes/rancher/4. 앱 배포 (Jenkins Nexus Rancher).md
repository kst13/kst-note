# 앱 배포 — Jenkins → Nexus → Rancher Apps

[3. DEV 클러스터 설치](3.%20DEV%20클러스터%20설치.md) 10장(VIP, Traefik, 인증서)까지 끝낸 뒤 진행한다. 예시는 기존에 Docker로 운영하던 Vue SPA `otw-web`이다. 같은 구조의 다른 프로젝트도 이 순서를 따른다.

역할은 이렇게 나눈다.

- **Jenkins:** 이미지와 차트를 같은 버전으로 만들어 Nexus에 올린다. 배포는 하지 않는다.
- **Rancher Apps:** 담당자가 버전을 골라 설치·업그레이드·롤백한다.

## 0. Docker 운영과 무엇이 다른가

### 기존 구조

```text
사용자 ─https─▶ Docker 서버 한 대
                ├ proxy 컨테이너 (443)  인증서, 80→443, 경로 나누기
                │    └─▶ :81
                └ web 컨테이너 (80)     화면 파일 + API 넘기기
```

### 지금 구조

```text
사용자 ─https─▶ <앱>.<도메인> = <DEV VIP>   (MetalLB, DEV 노드 한 대가 맡음)
                ▼
              Traefik (DEV 3대)              인증서, 도메인 보고 나누기
                ▼
              앱 Pod × 2                     nginx 하나: 화면 파일 + 기존 proxy·web 경로 규칙 전부
```

| 기존 | 지금 | 이유 |
|---|---|---|
| proxy 컨테이너 | Traefik(TLS, 도메인) + 앱 nginx(경로 규칙) | Traefik은 클러스터에 하나. 앱마다 proxy를 둘 필요가 없음 |
| `ssl/*.pem`을 이미지에 복사 | `kube-system`의 TLS Secret 하나 | 이미지를 받은 사람이 개인키를 꺼낼 수 없음. 갱신도 한 곳 |
| proxy → `서버:81` → web | 같은 nginx 안에서 처리 | 한 단계가 줄어듦 |
| 미리 빌드한 `dist`를 이미지에 복사 | Dockerfile 안에서 `npm ci`, `vite build` | 누가 어디서 빌드해도 결과가 같음 |
| `docker run` | Rancher Apps에서 Helm 차트 설치 | 버전 선택, 끊김 없는 교체, 롤백 |
| 서버 한 대 | Pod 2개가 노드 3대에 나뉨 | 노드 하나가 죽어도 서비스 유지 |

### 앱이 여러 개일 때

proxy가 하던 일을 두 곳으로 나눈다.

| 하던 일 | 맡는 곳 |
|---|---|
| TLS 인증서, 80→443 | Traefik (클러스터에 하나) |
| 도메인별로 앱 나누기 | 앱마다 Ingress 리소스 하나 (차트에 포함) |
| 경로, Referer, 경로 바꾸기, 레거시 서버, 스트리밍 설정 | 각 앱의 nginx |

공용 proxy 하나에 모든 앱 규칙을 모으지 않는다. 한 앱의 경로를 바꾸려고 공용 proxy를 다시 배포해야 하고, 설정 실수 하나가 모든 사이트를 멈추게 한다.

## 1. 저장소에 넣는 파일

```text
<앱 저장소>/
├── Jenkinsfile
├── Dockerfile
├── .dockerignore
└── deploy/
    ├── nginx/
    │   ├── default.conf.template   # proxy + web 규칙을 합친 nginx 설정
    │   ├── proxy-common.conf       # 모든 프록시 경로에 붙는 공통 헤더
    │   └── 05-resolver.envsh       # Pod의 DNS 서버를 nginx resolver에 넣음
    └── chart/                      # Deployment, Service, Ingress, values
```

`.gitignore`와 `.dockerignore`에 `ssl/`, `*.pem`, `*.key`, 예전 빌드 결과 폴더를 넣는다. 기존 Docker 방식의 인증서 폴더가 실수로 커밋되지 않게 한다.

브랜치는 `stage`에서 `develop`을 만들어 DEV 배포용으로 쓴다.

## 2. Dockerfile

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json .npmrc ./
RUN npm ci --no-audit --no-fund
COPY . .
ARG BUILD_MODE=development
RUN npx vite build --mode ${BUILD_MODE}

FROM nginx:1.28
RUN ln -sf /usr/share/zoneinfo/Asia/Seoul /etc/localtime
ENV OTW_API=http://<백엔드>:<포트> \
    LEGACY_HOST_HEADER=\$host \
    TRUSTED_PROXY_CIDR=10.42.0.0/16
    # … 백엔드 주소 기본값
RUN rm -f /etc/nginx/conf.d/default.conf
COPY deploy/nginx/default.conf.template /etc/nginx/templates/default.conf.template
COPY deploy/nginx/proxy-common.conf /etc/nginx/snippets/proxy-common.conf
COPY --chmod=755 deploy/nginx/05-resolver.envsh /docker-entrypoint.d/05-resolver.envsh
COPY --from=build /app/dist /usr/share/nginx/html
```

- **두 단계 빌드:** 최종 이미지에는 nginx와 화면 파일만 남는다.
- **`BUILD_MODE`:** Vite의 `VITE_*` 값은 빌드할 때 JS에 박힌다. 같은 이미지를 환경만 바꿔 쓸 수 없다. `development`(.env), `staging`, `production`을 환경마다 따로 빌드한다.
- **`package-lock.json`이 최신인지 본다.** `pnpm-lock.yaml`이 같이 있어도 최근에 갱신된 쪽을 쓴다. lock 파일에 `@rollup/rollup-linux-x64-musl`, `@esbuild/linux-x64`가 있어야 alpine에서 빌드된다.
- **`.npmrc`:** 사내 패키지(`@dns/*`)를 Nexus npm 저장소에서 받는다. 빌드하는 곳(Jenkins 서버)에서 Nexus 8081과 `registry.npmjs.org`에 닿아야 한다.
- **`\$host`:** Dockerfile `ENV`의 `$`는 escape한다. 템플릿에 nginx 변수 `$host`로 들어간다.

## 3. nginx 템플릿: proxy와 web을 하나로

`/etc/nginx/templates/*.template`은 nginx 공식 이미지의 기능이다. 시작할 때 `${변수}`를 환경변수 값으로 바꿔 `conf.d/`에 설정 파일을 만든다. 백엔드 주소가 환경마다 달라도 이미지를 다시 만들지 않는다.

### 합칠 때 지킨 원칙

**규칙 순서를 기존과 같게 맞춘다.** 기존에는 proxy 규칙을 먼저 거치고 남은 요청만 web으로 갔다. nginx location 우선순위는 다음과 같다.

1. `=` 정확히 일치
2. 가장 긴 접두사 중 `^~`
3. 정규식(`~`, `~*`), 파일에 적힌 순서
4. 가장 긴 일반 접두사

기존 proxy의 정규식(`\.do$`, 레거시 정적 파일)은 web 쪽 경로보다 먼저 걸렸다. 그래서 web 쪽 경로는 `^~` 없이 일반 접두사로 둔다.

| 요청 | 기존 | 합친 설정 |
|---|---|---|
| `= /members.do` | proxy: 302 `/404` | 같음 |
| `~ \.do$` | proxy → 레거시 서버 | 같음 |
| `~* ^/(css\|js\|calendar\|static\|images)` | proxy → 레거시 서버 | 같음 |
| `/api/oim/` | proxy → 회원 서버 (`/api/`로 바꿔서) | 같음 |
| `^~ /txm` | proxy → 파일 서버 (스트리밍) | 같음 |
| `/api/software`, `/api/dnc`, `/onehelp/` | proxy → web → 백엔드 | 바로 백엔드 |
| 그 밖 | proxy → web → `index.html` | 바로 `index.html` |

**Referer 규칙은 기존처럼 proxy의 `location /`를 거치던 경로에만 건다.** 레거시 `.do` 페이지에서 온 요청은 레거시 서버로 보낸다. `if` 안에서 `proxy_pass`를 쓰면 문제가 생기기 쉽다. 그래서 `if`에서는 418을 신호로 보내고 이름 붙은 location이 받는다.

```nginx
map $http_referer $from_legacy { default 0; "~*\.do" 1; }

error_page 418 = @legacy;

location / {
    if ($from_legacy) { return 418; }
    try_files $uri $uri/ /index.html;
}

location @legacy {
    include /etc/nginx/snippets/proxy-common.conf;
    proxy_set_header Host ${LEGACY_HOST_HEADER};
    proxy_pass $legacy;
}
```

### 쿠버네티스에 맞춰 바꾼 것

| 항목 | 기존 | 바꾼 것 | 이유 |
|---|---|---|---|
| 백엔드 주소 | `upstream { server host:port; }` | `set $otw_api ${OTW_API};` 후 `proxy_pass $otw_api;` | `upstream`은 시작할 때 DNS를 찾는다. 하나만 실패해도 nginx가 뜨지 않는다. 변수는 요청할 때 찾는다 |
| DNS | `resolver 8.8.8.8` | `resolver ${DNS_SERVER}` (`05-resolver.envsh`가 `/etc/resolv.conf`에서 읽음) | 사내 이름은 클러스터 DNS → 노드 DNS로 찾아야 한다 |
| TLS | proxy가 `listen 443 ssl` | `listen 80`만 | Traefik이 TLS를 푼다 |
| 사용자 IP | proxy가 직접 봄 | `set_real_ip_from 10.42.0.0/16; real_ip_header X-Forwarded-For;` | Traefik을 거치면 `$remote_addr`가 Traefik Pod IP가 된다 |
| `X-Forwarded-Proto` | `$scheme` (https) | Traefik이 준 값을 넘김 (`map $http_x_forwarded_proto`) | nginx에는 http로 들어온다 |
| 리다이렉트 | 절대 URL | `absolute_redirect off` | `http://…`로 내려가지 않게 한다 |
| 로그 | `txm_debug.log` 파일 | 기본 `access.log`(stdout) | Rancher·`kubectl logs`로 본다. 컨테이너 디스크가 차지 않는다 |

- 변수 `proxy_pass`는 search 도메인을 붙이지 않는다. 백엔드는 FQDN으로 쓴다.
- location 안에 `proxy_set_header`가 하나라도 있으면 바깥 설정이 상속되지 않는다. 공통 헤더는 `proxy-common.conf`로 빼서 각 location에서 `include`한다.
- envsubst는 정의된 환경변수만 바꾼다. nginx 변수(`$host`, `$uri`)는 소문자라 건드리지 않는다.

### 시작 로그

```text
Sourcing /docker-entrypoint.d/05-resolver.envsh
10-listen-on-ipv6-by-default.sh: info: /etc/nginx/conf.d/default.conf is not a file or does not exist
Running envsubst on /etc/nginx/templates/default.conf.template to /etc/nginx/conf.d/default.conf
```

IPv6 안내는 무시한다. 기본 `default.conf`를 지웠고 템플릿은 20번 스크립트에서 만들어진다. 10번 스크립트가 돌 때는 파일이 아직 없다. DEV는 IPv4만 쓴다.

## 4. Helm 차트

`docker run` 명령을 YAML로 적어 둔 묶음이다.

| 파일 | 하는 일 | Docker로 치면 |
|---|---|---|
| `deployment.yaml` | 컨테이너 2개를 유지. `/healthz`로 준비·생존 확인 | `docker run` + `--restart always` + 헬스체크 |
| `service.yaml` | Pod 2개 앞의 고정 이름. 요청을 나눠 줌 | `-p 81:80` |
| `ingress.yaml` | Traefik에 도메인 → Service를 알림. `tls.hosts`만 쓰고 `secretName`은 비움 | proxy의 `proxy_pass` |
| `values.yaml` | 이미지, 복제본 수, 도메인, 백엔드 주소 | `-e` 옵션들 |

- `ingress.tlsSecretName`을 비우면 Traefik 기본 인증서(와일드카드)를 쓴다.
- `backends.*`를 비우면 이미지 기본값(Dockerfile `ENV`)을 쓴다. 값이 있는 항목만 Deployment `env`로 들어간다.
- 버전 규칙: **이미지 태그 = 차트 버전 = `1.0.<빌드번호>`.** `latest`는 쓰지 않는다. 무엇이 떠 있는지, 무엇으로 되돌릴지 알 수 없어진다.

```bash
helm lint deploy/chart
helm template t deploy/chart --set backends.legacyHostHeader=<호스트> | less
```

## 5. Jenkins

```groovy
environment {
  NEXUS_DOCKER = '<NEXUS_HOST>:5000'
  NEXUS_HELM   = 'http://<NEXUS_HOST>:8081/repository/helm-hosted/'
  IMAGE        = "${NEXUS_DOCKER}/<그룹>/<앱>"
  BUILD_MODE   = 'development'
  VER          = "1.0.${env.BUILD_NUMBER}"
}
// 1. docker build --build-arg BUILD_MODE → login → push → logout
// 2. helm lint → helm package --version $VER --app-version $VER → curl --upload-file
```

Job 설정: New Item → Pipeline → **Pipeline script from SCM** → Git URL, GitLab 계정 → Branch `*/develop` → Script Path `Jenkinsfile`.

| 단계 | 증상 | 원인 |
|---|---|---|
| `npm ci` | `ETIMEDOUT`, `ECONNRESET` | Jenkins → `registry.npmjs.org` 막힘. Nexus npm 프록시로 우회 |
| `npm ci` | `401`/`404` (`@dns/*`) | `.npmrc` 토큰 또는 Nexus 권한 |
| `docker push` | `unauthorized` | Credentials 계정에 `docker-hosted` 쓰기 권한 없음 |
| `curl --upload-file` | `400` | 같은 버전 차트가 이미 있음. helm-hosted는 덮어쓰기 금지 |

빌드 뒤 nginx 설정을 Jenkins 서버에서 확인한다. Jenkinsfile이 push 직후 `docker logout`하므로 다시 로그인해야 받을 수 있다. 로그인 없이 받으면 `unauthorized`가 난다.

```bash
docker login <NEXUS_HOST>:5000
docker run --rm <NEXUS_HOST>:5000/<그룹>/<앱>:1.0.<N> nginx -t     # syntax is ok, test is successful
docker image rm <NEXUS_HOST>:5000/<그룹>/<앱>:1.0.<N>
docker logout <NEXUS_HOST>:5000
```

## 6. Rancher에서 설치

### 6.1 차트 저장소 등록 (클러스터마다 한 번)

`dev` → **Apps** → **Repositories** → **Create**

| 항목 | 값 |
|---|---|
| Target | **Helm Repository** (HTTP(S) URL pointing to a Helm chart repository index) |
| Name | `nexus` |
| Index URL | `http://<NEXUS_HOST>:8081/repository/helm-hosted/` |
| Authentication | 익명 읽기가 켜져 있으면 None, 아니면 HTTP Basic + 읽기 계정 |

**Active**가 되면 Rancher(MGMT)가 Nexus 8081을 읽은 것이다. 목록은 DEV가 아니라 MGMT의 Rancher Pod가 읽는다. 그래서 MGMT → Nexus 8081 방화벽이 필요하다.

### 6.2 설치

**네임스페이스를 먼저 정한다.** Apps 화면 위쪽 네임스페이스 필터를 앱 네임스페이스로 바꾼 뒤 시작한다. 그러면 Install 화면의 기본값도 그 네임스페이스로 잡힌다.

**Apps** → **Charts** → 저장소 필터 `nexus` → 앱 → **Install**

| 항목 | 값 |
|---|---|
| Namespace | 앱 이름 (예: `otw`). 없으면 새로 만들기 |
| Name | 앱 이름 |
| Version | 올린 버전 |
| Values | DEV 기본값이면 그대로 |

```bash
kubectl -n <ns> get pods,ingress            # Pod 2개 Running, HOSTS <앱>.<도메인>
kubectl -n <ns> logs deploy/<앱> --tail=20
```

PC에서 `https://<앱>.<도메인>/healthz`가 `200`이면 브라우저로 화면과 API 메뉴를 확인한다.

**실수 사례: `default` 네임스페이스에 설치.** Helm 릴리스는 네임스페이스를 옮길 수 없다. Installed Apps에서 지우고 다시 설치한다. 같은 도메인 Ingress가 두 네임스페이스에 동시에 있으면 Traefik이 어느 쪽으로 보낼지 헷갈리므로 **먼저 지운다.**

```bash
kubectl -n default get deploy,svc,ingress,pods -l app=<앱>     # No resources found
```

### 6.3 배포·롤백

| 작업 | Docker | Rancher |
|---|---|---|
| 새 버전 | 서버 접속 → `docker stop/rm/run` | Repositories → Refresh → Installed Apps → Upgrade → 버전 선택 |
| 교체 중 끊김 | 끊김 | 새 Pod가 `/healthz` OK가 된 뒤 옛 Pod를 내림 |
| 잘못된 버전 | 이미 내려간 뒤 알게 됨 | 새 Pod가 준비되지 않으면 옛 Pod가 계속 서비스 |
| 롤백 | 이전 태그를 찾아 다시 `docker run` | Installed Apps → Rollback → 리비전 선택 (이미지 + values) |
| 설정 값 변경 | 설정 수정 → 이미지 재빌드 | Upgrade 화면에서 values만 바꿈. 리비전으로 남음 |
| 로그 | `docker logs` | Pod → View Logs, `kubectl logs` |
| 셸 | `docker exec` | Pod → Execute Shell, `kubectl exec` |

경로 규칙 자체(새 `location` 추가)를 바꿀 때는 템플릿 수정 → 커밋 → Jenkins → Upgrade 순서다.

## 7. 지켜볼 것

- **레거시·백엔드가 받는 Host:** 요청 Host(`dev-…` 도메인)가 그대로 넘어간다. 백엔드가 모르는 이름이라 거절하면 values `backends.legacyHostHeader`에 아는 이름을 넣는다.
- **방화벽 출발지:** 앱 Pod의 nginx가 백엔드로 직접 나간다. 출발지가 기존 Docker 서버에서 DEV 노드 3대로 바뀐다. 화면은 뜨는데 API가 502면 이것부터 본다 (`kubectl -n <ns> logs deploy/<앱>`).
- **`.do`로 끝나는 SPA 경로:** `~ \.do$` 규칙에 걸려 레거시 서버로 간다. 기존 동작 그대로 두었다.
- **Traefik 설정 두 가지:** 80→443 리다이렉트와 긴 업로드·다운로드 시간 제한. [3. DEV 클러스터 설치](3.%20DEV%20클러스터%20설치.md) 10.5.
